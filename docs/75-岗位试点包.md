# 岗位试点包

## 1. 试点目标

用 1–2 个岗位、3–5 个低风险流程验证：

- 用户能否用自然语言完成
- 结果是否与目标一致
- 失败是否可处理
- 是否真的节省时间
- 是否具备推广条件

## 2. 岗位优先级

| 优先级 | 岗位 | 适合流程 | 风险 |
|---|---|---|---|
| P0 | 财务/运营 | Excel 汇总、对账、日报 | 低 |
| P0 | 行政/人事 | 文件整理、模板生成 | 低 |
| P1 | 销售助理 | 客户表清洗、报表 | 中 |
| P2 | 采购/客服 | 内部 API 查询 | 中 |
| 暂不做 | 爬虫/登录/强风控 | 1688/BOSS 等 | 高 |

首轮只做绿色场景：

```text
Excel / CSV
文件处理
内部 API
报表汇总
```

不做：

```text
扫码登录
外部网站抓取
写外部业务系统
验证码/滑块
```

## 3. 试点流程

```text
1. 选岗位和 1 个流程
2. 写目标契约：输入/输出/成功标志/边界
3. 用真实样例（脱敏）做 1 次
4. 做成插件
5. 目标一致性测试
6. 用户自然语言试用 3 次
7. 记录问题
8. 修复并复测
9. 用户签字验收
10. 决定是否进入下一流程
```

## 4. 目标契约模板

```text
岗位：
流程名称：
输入：
处理规则：
输出字段：
输出位置：
成功标志：
失败处理：
明确不做什么：
数据敏感级别：
验收人：
```

## 5. 试点指标

```text
任务成功率：3/3
结果一致：字段/数值/排序与人工一致
用户操作：全程自然语言，不看代码
耗时：比人工至少节省 50%
失败可恢复：有明确提示和重试
无 P0：无数据丢失、无越权、无密钥泄露
```

任一不满足，不进入推广。

## 6. 停止条件

```text
结果与人工不一致
需要用户改代码/参数
需要手工修数据超过 20%
出现权限/凭证/数据安全问题
用户无法用自然语言完成
```

## 7. 试点角色选择

建议首个试点：

```text
财务/运营的 Excel 汇总
```

原因：

- 输入输出明确
- 不依赖登录和外部风控
- 容易做目标一致性测试
- 失败可人工兜底

## 9. 推广门槛

```text
[ ] 至少 1 个岗位完成 3 次真实任务
[ ] 用户签字验收
[ ] 目标一致性测试通过
[ ] 安装/升级/回滚通过
[ ] 健康检查无告警
[ ] 有失败处理和回滚说明
[ ] 有发布说明
```
