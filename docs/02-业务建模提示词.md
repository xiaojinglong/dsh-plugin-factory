# 02 · 业务建模提示词（S3 流程初稿 + S5 终稿回填）

> 用法：S3 用阶段 A/B/C 产出《节点流程.md》；S5 用阶段 E 把实测事实回填进 SKILL.md。
> 原则：**不理解就追问，禁止猜业务规则；没有实测，不许写"字段校准"。**

---

## 输入

- 业务中文名 / 业务标识
- 一段大白话业务描述（或现有业务文档）
- 可选：报表样例、表头、现有 SKILL.md、MCP 工具清单
- S5 时额外输入：**实测产物**（taskId、汇总表路径、明细路径；用 `read_result_file` 读取）

---

## 阶段 A：事实清单（先不写文档）

| 类别 | 必须明确 | 状态 |
|---|---|---|
| 业务目标 | 解决什么问题、产出什么、给谁做决策 | |
| 使用角色 | 谁发起/执行/验收/查看 | |
| 触发方式 | 何时用、频率、由谁触发 | |
| 数据来源 | 哪个系统/服务/文件；爬虫型还是 API 型 | |
| 业务步骤 | 从取数到产出的完整节点 | |
| 规则与阈值 | 判断标准、筛选条件、公式、边界 | |
| 数据粒度 | 店铺/订单/产品/计划级；主键是什么 | |
| 金额口径 | 币种、单位、精度、时区 | |
| 权限与审批 | 是否扫码/授权/审批；写操作边界 | |
| 输入参数 | 用户需要提供什么（范围/日期/阈值） | |
| 输出 | 文件/报告结构、章节、存放位置 | |
| 异常处理 | 失败/缺数据/需人工介入怎么办 | |
| 验收标准 | 怎么算做对；抽查方式 | |
| 术语 | 站点/线路/店铺/站长等业务词定义 | |
| 工具现状 | 是否已有 MCP；没有则标待开发 | |
| 多数据源 | 几个服务/接口；先后顺序；可否并行 | |
| 写操作 | 哪些动作会改业务系统；是否必须审批 | |
| 幂等/防重 | 重复提交如何识别 | |
| 验证/回滚 | 多久验证、失败是否回滚 | |
| 审计 | 留什么记录 | |

缺的标 `【缺失】`。

## 阶段 B：追问（Gate，必须执行）

1. 只问会改变文档内容的问题，不问技术实现。
2. 每轮 ≤ 8 个，按重要性排序，给选项与推荐默认值。
3. 用户答"不知道/你定" → 用合理默认值并标 `【默认，待确认】`。
4. 材料已明确的不要重复问。
5. 禁止在关键信息缺失时编造。

## 阶段 C：生成《{业务中文名}节点流程.md》（S3 产出）

7 章：业务目标 / 角色与职责 / 节点流程（编号、大白话）/ 输入与输出 / 异常处理 / 口径说明 / 版本与对齐记录。
禁止出现工具名、状态码、英文字段名。结构见 `templates/节点流程.md.skeleton.md`。

## 阶段 D：生成 SKILL.md 初版（章节齐全，业务内容留待回填）

10 章：frontmatter / 适用场景 / 前置条件与输入 / 工具清单 / 业务编排流程 / 数据规则 / 数据校验 / 输出模板 / 异常与重试 / 维护与待确认。
要求：
- 工具清单只列真实存在的 5 个工具；多数据源按来源分组。
- 阈值写显式数值（如 `≥ 0.15`），公式写公式。
- 输出模板固定章节，便于验收。
- 写操作必须写审批 Gate。
- **阶段 D 产出的 SKILL.md 标记为「初版·待实测校准」，不得当终稿。**

## 阶段 E：实测回填（S5，关键新增）

输入实测产物后，逐项执行：

1. 读汇总表：记录**真实列名**（哪些列用于销售额/毛利/成本）、是否含"合计"行、合并单元格情况、特殊值（`–∞`/空/`-`）。
2. 读明细：记录粒度（订单级/产品级）、首行是否汇总行、关联键、可分析字段、缺失字段。
3. 跑口径校验：
   - 汇总 vs 明细勾稽（例：`Σ明细毛利润（估） − 退损 = 汇总毛利润`）
   - 主键唯一性、总订单量/金额是否吻合
   - 记录所有不一致（如"净利润 ≠ 毛利 − 运营成本"）并标注【待确认】
4. 回填 SKILL.md 三节：
   - **§字段校准（YYYY-MM-DD 实测）**：真实列名、脏值规则、剔除规则、特殊值
   - **§口径核验**：勾稽结果、允许误差、不一致项
   - **§待确认清单**：币种/周期/口径未定项
5. 更新输出模板：补"数据口径"小节（任务 ID、文件数、缺失清单、异常说明）。
6. 章节顺序调整：把「字段校准」放到编排流程之后、规则之前。

## 自检（交付前逐项）

- [ ] 两份文档业务目标/步骤/阈值/输入输出一致
- [ ] SKILL.md 工具调用顺序与节点流程一一对应
- [ ] 字段校准带实测日期，且每条能在产物里找到依据
- [ ] 所有 `【待确认】/【默认】` 已集中列出
- [ ] 未编造字段/接口/阈值
- [ ] frontmatter `name` = 目录名 = kebab-case；description 含触发词
- [ ] 业务说明书无技术黑话
- [ ] 写操作有审批 Gate
- [ ] SKILL.md 无页面操作代码

## 输出格式

```text
## 阶段 A 事实清单
## 阶段 B 需要确认的问题（N 个，选项+默认值）
——（用户回答后）——
## 阶段 C 节点流程.md
## 阶段 D SKILL.md 初版
——（跑完执行层、拿到实测产物后）——
## 阶段 E 实测回填（patch：只输出需要替换的三节 + 变更说明）
```
