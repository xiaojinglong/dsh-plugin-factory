# 插件工厂运维手册

## 1. 健康检查

```powershell
node scripts/factory-health.cjs
node scripts/factory-health.cjs --json
```

检查：

- 控制面 `/health`
- 最近 24 小时失败任务
- staging 数量
- 已安装插件数
- 数据目录大小
- 控制面 token 是否配置

退出码：

```text
0 = 正常
1 = 控制面不可用
2 = 有告警（失败任务/数据量/token）
```

示例：

```text
工厂健康
  控制面：up 0.1.0
  请求：85，失败 0，staging 7
  已安装插件：1
  数据量：232.4MB
  告警：无
```

## 2. 安装 / 升级 / 回滚

安装：

```powershell
node scripts/dsh-factory.cjs install "<zip>" --profile desktop
```

升级同 id：

```powershell
node scripts/dsh-factory.cjs install "<new-zip>" --profile desktop
```

回滚预览：

```powershell
node scripts/dsh-factory.cjs rollback <id> --dry-run
```

回滚：

```powershell
node scripts/dsh-factory.cjs rollback <id> --profile desktop
```

## 3. 常见故障

### profile 依赖损坏

现象：

```text
profile 依赖损坏：<pkg> -> <path> 不存在
```

处理：

```powershell
node scripts/dsh-factory.cjs install "<zip>" --profile desktop
```

如果仍失败，先移除坏 link：

```text
plugin_manager remove_bundle "<pkg>"
```

### 控制面不可用

```powershell
npm run control-plane
node scripts/factory-health.cjs
```

### 数据目录过大

```powershell
node scripts/factory-health.cjs --json
```

超过 1GB 会告警；清理旧的 `data/generator/runs` 和 `data/jobs`，保留最近版本与审计所需的记录。

## 4. 发布前检查

```text
[ ] 健康检查退出码 0
[ ] 最近 24h 无失败任务
[ ] 已安装插件数符合预期
[ ] 安装/升级/回滚至少各跑一次
[ ] 目标一致性测试通过
[ ] 真实用户验收完成
```

## 5. 回滚原则

- 先 dry-run 确认版本
- 回滚只改 profile 链接，不删除历史 zip
- 重启 DSH 后生效
- 回滚后立即跑一次健康检查
