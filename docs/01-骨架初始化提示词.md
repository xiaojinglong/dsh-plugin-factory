# 01 · 骨架初始化提示词（S2）

> 用法：在总控流程 S2 使用；也可单独发给 AI。入参：业务标识、业务中文名、端口、taskType。
> 目标：只生成**空模板骨架**，不写任何业务内容（业务内容由 02/04 负责）。

---

## 输入

- `{业务标识}`：英文，kebab-case（如 `ad-effect-weekly`）
- `{业务中文名}`：如 `广告投放周报`
- `{端口}`：如 `8790`（登记表全局唯一）
- `{taskType}`：如 `ad_effect_weekly`
- `{仓库根}`：如 `D:\www\dshskills`

## 一、业务标识规范化（最高优先级）

- 合法：`^[a-z0-9]+(-[a-z0-9]+)*$`
- 大写/空格/下划线/PascalCase/中文 → 先转 kebab：转小写 → 非 `a-z0-9` 替换 `-` → 合并 `-` → 去首尾 `-`；回显让用户确认。
- 无法规范化（纯中文）→ 停止，要求用户给英文标识。
- **目录名 = SKILL.md 的 `name` = MCP 目录名 = patch 的 serverName**，四者一致。

## 二、目录存在保护（最高优先级）

创建前检查，任一路径已存在 → **立即停止，不覆盖/不删除**，列清单并要用户确认：

```
{仓库根}/tools/{业务标识}-mcp/
{仓库根}/skills/{业务标识}/
```

## 三、目标目录结构（固定，不增不减）

```
{仓库根}/
├── tools/{业务标识}-mcp/
│   ├── package.json      # 依赖仅 @modelcontextprotocol/sdk / zod / xlsx
│   ├── config.json       # 唯一配置入口（见第四节）
│   └── index.js          # 通用薄壳骨架（与模板实现保持一致）
└── skills/{业务标识}/
    ├── SKILL.md          # 只放空模板（章节齐全、无业务内容）
    └── {业务中文名}节点流程.md   # 只放空模板
```

## 四、config.json 规范（必须按此结构生成，默认值留空）

```json
{
  "service": { "baseUrl": "", "token": "", "authHeader": "authorization", "authScheme": "Bearer", "headers": {}, "timeoutMs": 30000 },
  "polling": { "intervalMs": 3000, "timeoutMs": 600000 },
  "endpoints": {
    "submit":   { "method": "POST", "path": "/jobs" },
    "status":   { "method": "GET",  "path": "/jobs/{taskId}" },
    "result":   { "method": "GET",  "path": "/jobs/{taskId}/result" },
    "verifyQr": { "method": "GET",  "path": "/jobs/{taskId}/verify" }
  },
  "submitBody": { "taskKey": "task", "paramsKey": "" },
  "statusMap": { "queued": "queued", "waiting_verify": "waiting_verify", "running": "running", "done": "succeeded", "failed": "failed" }
}
```

规则：
- `{taskId}` 占位由 index.js 替换并编码；`submitBody.taskKey="task"`、`paramsKey=""` 表示参数平铺进 body。
- 环境变量优先：`MCP_SERVICE_BASE_URL` / `MCP_SERVICE_TOKEN` / `MCP_POLL_INTERVAL_MS` / `MCP_POLL_TIMEOUT_MS`。
- 禁止写真实 token；`baseUrl` 留空，由 S6 装配时填写。

## 五、index.js 要求

- 直接拷贝标准实现，不要重写：`D:\www\dshskills\tools\concise-analysis-mcp\index.js`
- 5 个工具：`submit_task` / `get_task_status` / `wait_task` / `get_task_result` / `read_result_file`
- 导出 helper（`loadConfig`/`mapTaskStatus`/`fillPath`/`buildUrl`/`parseResultFile` 等），`require.main === module` 时才启动，便于 `node -e` 自测。
- 不写死业务字段、服务地址、账号。

## 六、依赖安装

```bash
cd tools/{业务标识}-mcp && npm i @modelcontextprotocol/sdk zod xlsx
```

- **失败降级**：无网络/无权限时，从任一已装好依赖的 MCP 目录拷贝 `node_modules`（版本一致即可），并在交付说明里注明。
- 验收：`node --check index.js` 通过。

## 七、空模板要求（关键修订）

- `SKILL.md`：只生成章节骨架（frontmatter + 10 章标题 + 空表格），**不得写入任何业务内容**。
- `{业务中文名}节点流程.md`：只生成 7 章骨架。
- 章节骨架见 `templates/SKILL.md.skeleton.md`、`templates/节点流程.md.skeleton.md`。

## 八、登记表

初始化成功后，在 `{仓库根}/registry.md` 追加一行（模板见 `templates/registry.md`）：
业务标识 | 中文名 | skill 目录 | mcp 目录 | serverName | taskType | 端口 | 数据目录 | 状态 | 维护人

## 九、验收清单

- [ ] 目录/文件清单与第三节完全一致
- [ ] `package.json` 依赖仅 3 个
- [ ] `config.json` 可 `JSON.parse`，`baseUrl` 为空
- [ ] `node --check index.js` 通过
- [ ] `SKILL.md` 只有空模板，无业务内容
- [ ] 四者命名一致（目录/name/ mcp 目录/后续 serverName）
- [ ] registry 已追加一行

## 十、红线

不启动服务、不做业务测试、不写业务流程、不覆盖已有目录、不引入多余依赖。
