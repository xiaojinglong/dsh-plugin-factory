# 39 — 岗位场景插件矩阵（2026-11-15）

> 目标：不只用 fixture 跑通，而是按真实岗位工作流做业务规则、异常分级、可执行建议和 HTML 报告。

## 2. 证据

- 场景源：`scenarios/<id>/fixture.json` + `runner.js`
- 批量生成：`scenarios/run-all.mjs`（9 个 request 全部到 `staging`）
- 验收/安装：`scenarios/accept-install*.mjs`
- 任务/报告：`scenarios/run-installed.mjs` → `scenarios/scenario-results.json`
- 报告：`plugins/<id>/report/<id>-report.html`（9/9 生成，KPI 4 个 + 明细 + 建议）
- 需求单：`data/generator/runs` 与 `scenario-results.json` 内 requestId

## 3. 本轮压测暴露并修复的工厂问题

| 问题 | 影响 | 修复 |
|---|---|---|
| staging 校验硬编码 `rows === 2` | 任何真实业务 >2 行都失败 | 改为 `rows > 0` + task 匹配 |
| 共享报告模板 `table(..., sevRows)` 传字符串 | 有 severity 的场景报告必崩 | 改为直接 HTML 表格 |
| 生成 `server.js` 固定 `../../../../` 找根 | staging 有 FACTORY_ROOT 能跑，安装后启动失败 | 模板向上查找 `platform/factory/bootstrap`；安装器兜底重写 |
| install `--force` rename 失败时 catch 删除原目录 | **安装失败反而丢插件** | 只删除本次新建路径；未备份的原有目录绝不删 |
| 测试硬编码 11/12 条 patch、只认字面 bootstrap | 新增插件后误报 | 动态计算业务条目；兼容 `path.join` 写法 |
| 报告模板只在生成时复制 | 已 staging 的旧包仍带旧模板 | 安装/场景脚本支持替换；后续生成自动带新模板 |

## 4. 质量结论

- 9/9 场景：staging 通过、任务 `done`、报告生成。
- 业务规则不是“demo 表格”：每个场景有分级、阈值、建议动作、风险金额/时段/百分比。
- 工厂自身修复了 6 个真实问题（其中安装器删除原目录属高危），回归 81/81、doctor 全绿（仅 legacy warn）。
- 仍为本地 fixture；真实数据接入需替换 fixture/runner 数据源，并做业务口径确认。

## 5. 仍未覆盖

- 真实外部 API/登录态（除 haina 真实写）；浏览器类页面巡检未纳入本轮。
- 大规模数据量/并发/性能压测；目前是 7–10 行级业务样本。
- 跨岗位审批流（如招聘 offer 审批、预算审批）未做状态机。
