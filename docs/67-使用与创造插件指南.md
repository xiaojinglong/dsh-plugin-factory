# 67 — 使用与创造插件指南（另一台机器版）

> 适用于 Windows + DSH 桌面版 + Node 24。  
> 仓库路径示例：`D:\dsh-plugin-factory`，按你的实际路径替换。

## 0. 最推荐：在 DSH 对话里直接说

不需要写命令。重启 DSH 后，直接在对话里描述工作流，例如：

```text
请把我的工作流做成一个插件：
每天读取订单 Excel，金额 >= 100 标记为高额，
金额 <= 0 标记为异常，其他标记正常，
输出一个新文件，不覆盖原文件。
```

DSH 的 `factory-agent` 会：

1. 问清输入、规则、输出、凭证、边界
2. 判断是否已有插件可复用
3. 在后台编写 portable 插件实现
4. 调用 `factory-control` 的 `create_plugin`
5. 自动生成、校验、导出 zip、安装到 DSH
6. 告诉你工具名，并提示重启 DSH

**你不需要写代码、不需要执行 pipeline、不需要改 manifest。**

如果 DSH 说找不到 `create_plugin`：重启 DSH，让它加载新版 `factory-control` MCP。

## 1. 前提

另一台机器需要：

- Windows
- Node.js 24+
- DeepSeek Harness 桌面版
- Git（可选，也可以直接拷贝仓库目录）
- 浏览器类插件需要 Playwright Chromium（`install.cmd` 会处理）

## 2. 安装工厂

```powershell
cd D:\dsh-plugin-factory
.\install.cmd
```

`install.cmd` 会：

1. 检查 Node 24
2. 检查 DSH profile
3. 安装 npm 依赖
4. 安装 Playwright Chromium
5. 生成/修复 DSH patch
6. 启动控制面（默认不启动 30 个测试插件）
7. 安装登录自启

已安装过时再次执行 `install.cmd` 只做检测，不会重复安装。

如果 profile 不是 `desktop`：

```powershell
.\install.cmd --profile <profile-name>
```

只检查、不启动：

```powershell
.\install.cmd --check
```

不自动启动服务：

```powershell
.\install.cmd --no-start
```

## 3. 启动、停止、自检

```powershell
# 平滑重启控制面（默认不启动 30 个测试插件）
.\start-factory.cmd

# 需要开发/测试 30 个旧插件时
.\start-factory.cmd --with-plugins

# 停止
.\stop-factory.cmd

# 自检
node platform/factory/cli.cjs doctor

# 查看服务状态
node platform/factory/cli.cjs status
```

Linux/macOS：

```bash
./start-factory.sh
./start-factory.sh --with-plugins
./stop-factory.sh
```

控制面地址：

```text
http://127.0.0.1:8780
```

## 4. 让新机器使用独立 token（推荐）

公开仓库里的旧 token 已失效；新机器建议生成本机独立 token：

```powershell
.\install.cmd --no-start
node scripts/rotate-service-tokens.cjs --apply
.\start-factory.cmd
node scripts/verify-service-tokens.cjs
```

新 token 只写：

```text
platform/secrets/service-tokens.json
```

该文件已 gitignore，不要提交。

## 5. 关于已有 30 个插件

这 30 个是**工厂开发/测试产物**：

- 默认**不启动服务**
- 默认**不写入 DSH patch**
- DSH 工具列表里不会出现它们

需要开发/测试服务时：

```powershell
.\start-factory.cmd --with-plugins
```

但这只启动服务进程，**不会重新注册 DSH 工具**。  
如果确实要在 DSH 里使用某个旧插件，需要单独生成 bundle 或显式加入测试 patch（不推荐作为日常路径）。

要创建可用的新插件，直接用 portable-host 对话流程。

## 6. 创造新插件（默认 portable）

新插件默认走 `portable-host`，不依赖工厂服务。

### 6.1 提交需求

```powershell
$token = (Get-Content .\data\control-plane\token -Raw).Trim()
$payload = @{
  brief = '生成一个 portable 插件：统计 JSON 行数'
  params = @{
    pluginId = 'my-portable'
    name = 'My Portable'
    fixture = 'D:\data\sample.json'
    toolName = 'my_portable'
    description = 'Count rows in a JSON fixture.'
  }
} | ConvertTo-Json -Depth 8

$req = Invoke-RestMethod -Method Post `
  -Uri 'http://127.0.0.1:8780/requests' `
  -Headers @{ Authorization = "Bearer $token" } `
  -ContentType 'application/json' `
  -Body $payload
```

`target` 不写时默认 `portable-host`。旧 MCP 流程必须显式：

```json
"target": "mcp"
```

### 6.2 运行 pipeline

```powershell
$env:CONTROL_PLANE_TOKEN = $token
node apps/generator/pipeline.cjs --request $req.request.id
```

成功后会生成：

```text
data\generator\runs\<requestId>\<pluginId>\
data\generator\runs\<requestId>\dist\<pluginId>-0.1.0.zip
```

### 6.3 验收并安装

```powershell
Invoke-RestMethod -Method Post `
  -Uri "http://127.0.0.1:8780/requests/$($req.request.id)/accept" `
  -Headers @{ Authorization = "Bearer $token" } `
  -ContentType 'application/json' `
  -Body (@{ acceptedBy = 'me'; note = 'ok' } | ConvertTo-Json)

$zip = Get-ChildItem "data\generator\runs\$($req.request.id)\dist\*.zip" | Select-Object -First 1
node scripts/dsh-factory.cjs install $zip.FullName --profile desktop
```

然后重启 DSH。新工具名就是 `toolName`，例如：

```text
my_portable
```

## 7. 自定义业务逻辑

在请求里加 `implFile`（ESM 文件）：

```js
// D:\data\my-impl.mjs
export async function execute(args = {}) {
  return { ok: true, received: args }
}
```

请求参数：

```json
"implFile": "D:\\data\\my-impl.mjs"
```

生成器会把它复制为 `lib/impl.js`，`index.js` 直接调用 `execute(args)`。

如果业务需要第三方依赖，生成后编辑：

```text
data\generator\runs\<requestId>\<pluginId>\package.json
```

再加依赖，然后重新导出/安装。

## 8. 手动从现有 portable 插件复制

```powershell
Copy-Item portable-plugins\excel-status-mark portable-plugins\my-excel -Recurse
```

修改：

- `package.json` 的 `name`
- `cordis.patch.yml` 的包名
- `index.js` 的 tool name / 描述
- `lib/impl.js` 的业务逻辑

导出：

```powershell
node scripts/export-plugin.cjs --id my-excel --out dist
```

## 9. 注册 legacy 插件 `concise-analysis`

它默认不会进 DSH，因为 `legacy:true`。在另一台机器上复现：

```powershell
# 1. 启动控制面 + 测试插件（concise-analysis 是旧服务）
.\start-factory.cmd --with-plugins

# 2. 生成它的 MCP bundle
node scripts/export-mcp-bundle.cjs `
  --id concise-analysis `
  --include-legacy `
  --server-name concise-analysis

# 3. 安装 bundle
node scripts/dsh-factory.cjs install bundles\concise-analysis-mcp-bundle --profile desktop
```

重启 DSH 后使用：

```text
mcp__concise-analysis__submit_task
```

它需要钉钉扫码登录。扫码：

```powershell
# taskId 从 submit_task 返回
Invoke-WebRequest `
  -Uri "http://127.0.0.1:8790/jobs/<taskId>/verify" `
  -OutFile .\concise-qr.png
```

扫码完成后任务会自动继续。

## 10. 凭证与安全

- DPAPI 加密的凭证不能跨机器复制，必须在新机器重新配置。
- 浏览器插件需要重新登录/storageState。
- 不要把 `platform/manifests`、`plugins/*/manifest.json`、`platform/secrets/service-tokens.json` 提交到 public 仓库。
- 新 token 只在本地 overlay；不要 `git add -A`。
- 工厂公开仓库历史里的旧 token 已失效。

## 11. 常见问题

### DSH 里没有工具

1. 确认服务在跑：`node platform/factory/cli.cjs status`
2. 确认 patch：`node platform/factory/cli.cjs doctor --health`
3. 重启 DSH
4. 检查 `platform/manifests/<id>.json` 是否 `legacy:true`

### 服务全 DOWN

```powershell
.\start-factory.cmd
```

登录自启只发生在 Windows 登录；DSH 应用单独重启不保证拉起后台栈。

### `concise-analysis` 一直等待

它需要钉钉扫码；见第 9 节。

### 安装后工具没出现

- `dsh-factory` 写入 profile 后需要重启 DSH
- 检查 profile：`%USERPROFILE%\.dsh\profiles\desktop\package.json`
