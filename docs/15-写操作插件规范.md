# 15 · 写操作 / 浏览器 / 文件系统 插件规范

> 来源：2026-11-14 haina-comment 实测（登录博客 → 发 10 条评论 → 汇总报告）。
> 适用：凡是要**修改外部系统**（评论、下单、调价、发消息、上传、删除）或**操作本机资源**（浏览器、文件夹）的插件。

---

## 一、先分类：三类执行层

| 类型 | 适用 | 执行层 | 关键约束 |
|---|---|---|---|
| API 型 | 有可用接口 | `api-runner.js` + fetcher 配置 | 只读默认；写接口必须 Gate |
| 浏览器型 | 只有页面/UI | Playwright（`crawler.js`） | 选择器集中、禁止 sleep 同步、截图留证 |
| 文件系统型 | 本机文件/目录 | Node `fs` | 只读扫描默认；写文件需指定目录白名单 |

同一插件可混用（例：haina-comment = 文章列表走 API + 评论走浏览器）。

## 二、写操作四道闸（缺一不可）

1. **dry_run 预演**：`params.dry_run=true` 只生成计划/填充不提交，产物标记 `status=planned`。
2. **显式确认**：必须 `params.confirm_write=true` 才真正提交；否则任务 `failed`，错误信息说明如何预演。
3. **逐条审计**：每条写操作记录 `seq / 目标(article_id) / 内容 / status / http_status / 站点回执 / 时间`，落盘 JSON。
4. **限速与停止**：默认每条 2.5–4 秒；连续 3 条失败立即停止；单任务上限（评论 ≤20、其他按业务定）。

## 三、结果语义（必须写清）

| 状态 | 含义 | 报告怎么写 |
|---|---|---|
| `submitted` | 接口/页面返回成功 | "已提交" |
| `pending`（站点有审核） | 提交成功但待审核 | "已提交，待站点审核后展示" |
| `failed` | 明确失败 | 附错误与 HTTP 状态 |
| `planned` | 预演未提交 | "预演，未提交" |

> 禁止把"提交成功"写成"已生效/已发布"。haina 实测：`评论成功，等待审核`。

## 四、审计与留证（写操作必做）

- 审计 JSON：`<task>_audit.json`，字段见第二节；与报告一一对应。
- 页面型写操作建议留 1 张关键截图（提交后页面/成功提示）。
- 报告附录必须写：数据来源、任务号、账号（脱敏）、时间、限制（审核/延迟/不可回滚）。

## 五、幂等与防重

- 每条写操作带业务键（如 `article_id + 内容 hash`），同一任务内不重复提交。
- 跨任务重跑时，报告/审计要能看出"这是第几次跑、重复了哪些"。
- 批量写操作默认串行，不做并发（页面型尤其禁止并发）。

## 六、回滚与清理

- 能删除的先确认有删除接口/页面入口；没有则报告必须提示"需人工清理"。
- 写操作前记录"变更前状态"（如已有评论数），便于事后核对。
- 失败重试仅做 1 次；仍失败进入失败清单，不无限重试。

## 七、安全红线

1. 凭证只放服务端 `.env`（`HAINA_EMAIL/HAINA_PASSWORD`），不进 SKILL、报告、日志。
2. 报告账号脱敏（`791***@qq.com`）。
3. 不绕过验证码/风控/审核；不伪造用户身份。
4. 写操作范围默认"最小且可解释"（本场景：指定文章、指定条数、测试文案标注）。

## 八、验收清单（写操作版）

- [ ] 未传 `confirm_write` → 任务 failed 且错误可读（闸门生效）
- [ ] `dry_run=true` → 只出计划，产物 `status=planned`，外部系统无变化
- [ ] 正式跑：成功数 = 计划数（或失败清单完整）
- [ ] 审计 JSON 逐条含目标/内容/状态/回执/时间
- [ ] 报告写清"待审核/不可回滚/需人工清理"
- [ ] 凭证未出现在报告/日志；账号已脱敏
- [ ] 工厂自检通过（含报告存在性）

## 九、本次实测（haina-comment）

| 项 | 结果 |
|---|---|
| 闸门 | 不传 confirm_write → failed：`写操作保护：需显式传 confirm_write=true…` |
| 预演 | `dry_run=true` → 3 条 planned，站点无变化 |
| 正式 | `confirm_write=true, max_comments=10` → **10/10 submitted**（均"等待审核"），耗时 77 秒 |
| 审计 | 10 条记录，含 article_id/内容/HTTP/回执/时间 |
| 报告 | 8 节，含逐条审计、按文章汇总、失败与异常、限制与未决 |
| 部署 | 8796 端口；MCP 五连通过；工厂自检 7 插件全绿 |
