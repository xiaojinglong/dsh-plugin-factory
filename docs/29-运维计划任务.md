# 29 — 运维计划任务（M6）

> 目的：把巡检/备份/演练变成可执行的计划任务；生成物需 owner 审核后再注册。

## 生成

```powershell
npm run ops:schedule -- --out .\ops --data-root .\data --token-file .\data\control-plane\token
```

产出（`ops/`，已 gitignore）：

- `ops-schedule.json`：任务清单（名称/频率/命令）。
- `crontab.txt`：Linux/macOS cron 行。
- `ops-tasks.ps1`：Windows `schtasks /Create` 行（不自动执行）。

## 任务

| 任务 | 频率 | 说明 |
|---|---|---|
| factory-health-check | 每 5 分钟 | `health-check`，失败可走 webhook |
| factory-backup | 每日 02:00 | `ops-backup` → 控制面 `/admin/backup` |
| factory-pilot-drill | 每周一 04:00 | `pilot-drill`（临时数据根演练） |

## 手工操作

```powershell
# 备份
npm run ops:backup -- --token-file .\data\control-plane\token

# 巡检（失败退出码 1，可接告警）
npm run health-check -- --token-file .\data\control-plane\token

# 演练
npm run pilot-drill

# 备份保留（默认 dry-run；--apply 只保留最新 N 份）
npm run ops:backup-prune -- --data-root .\data --keep 7
npm run ops:backup-prune -- --data-root .\data --keep 7 --apply
```

## 注意

- 生成的任务命令使用当前 Node 绝对路径；换机需重新生成。
- Windows 计划任务需要相应权限；owner 审核 `ops-tasks.ps1` 后再执行。
- 备份/恢复前先确认控制面已停止（恢复要求）。
- 未实现：邮件/短信告警、自动清理调度（目前提供命令，需外部调度器）。
