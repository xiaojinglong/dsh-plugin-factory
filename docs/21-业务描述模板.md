# 21 · 业务描述模板（业务人员填这个，交给 AI）

> 用法：填好下面 8 行，和 `20-一键造插件提示词.md` 一起发给 AI。
> **写不清也没关系**：只写第 1、2、3 行也能开工，AI 会用默认值并在交付时列「【默认】项」。

```
1. 业务名称：<中文名>（如：缺货预警）
2. 解决什么问题 / 产出什么：<一句话，如：找出在售商品的缺货风险并给补货建议，出一份 HTML 报告>
3. 数据从哪来：<系统/接口地址/页面>（如：POST https://api.giikin.com/agent/shopee/user/openapi/listing/listing）
4. 业务步骤：<取数→算→判断→出结果>（如：取 2 页在售商品 → 算缺货/低库存 → 按严重度排序 → 出报告）
5. 规则与阈值：<达标线/异常判定/公式>（如：总库存=0 为缺货；1-10 为低库存；30 天有单且库存 0 为高危）
6. 边界：<只读/含写操作>（如：只读，不调价不下架）
7. 怎么算做对：<抽查什么、谁签字>（如：抽查 3 个商品的库存与报告一致）
8. 其他要求：<报告格式/采样页数/时间范围>（如：2 页、HTML、按站点分组）
```

## 示例 A（最省事，3 句话）

> 帮我做一个"缺货预警"插件。数据用 listing 接口（POST api.giikin.com/agent/shopee/user/openapi/listing/listing），取陈雄德名下在售商品 2 页。找出总库存为 0 或 ≤10 的商品，按严重度排序出 HTML 报告，只读。

## 示例 B（完整填写）

```
1. 业务名称：缺货预警
2. 解决什么问题：在售商品缺货/低库存风险盘点，给补货优先级，出 HTML 报告
3. 数据从哪来：POST https://api.giikin.com/agent/shopee/user/openapi/listing/listing（Bearer 已配在服务端）
4. 业务步骤：取前 2 页在售 → 计算总库存与近 30 天销量 → 分缺货/低库存/健康 → 按"有销量且缺货"排序 → 出报告
5. 规则：缺货=总库存0；低库存=1~10；高危=30 天有单且缺货；总库存=normal_stock+warehouse_stock_total+oversea_stock
6. 边界：只读，不补货不下架
7. 验收：抽查 3 个商品库存与 job 数据一致
8. 其他：2 页采样、单文件 HTML、按站点分组、报告里写清样本覆盖率
```

## 示例 C（有接口文档时）

> 按 `20` 流程做，接口信息：URL `…/ads/list`，必填 `shop_id` 与 `date_time` 数组；周期 2026-11-01～11-13；店铺 1097451512；2 页；只读；出广告效果报告。

## 业务人员最常漏的 3 项（AI 会追问）

| 漏项 | 默认值（AI 会先按这个做） |
|---|---|
| 采样页数 | 2 页 |
| 报告格式 | 单文件 HTML（8 节） |
| 数据范围/负责人 | 沿用现有配置（陈雄德 632016） |
