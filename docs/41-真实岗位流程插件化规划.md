# 41 — 真实岗位流程插件化规划（只做流程拆解，不含实现）

> 目标：用真实岗位流程压测工厂“生产插件”的能力，而不是继续堆 fixture 数量。
> 结论：5 个岗位都能拆分，但应按 **A 离线可测 / B 登录只读 / C 写操作** 三档推进；不建议一上来做 BOSS 批量打招呼、1688 询价/样品单这类高风险写操作。

## 0. 可行性分级

| 档 | 定义 | 适合先做 | 工厂压测点 |
|---|---|---|---|
| **A 离线可测** | 输入导出 CSV/JSON/本地仓库，不登录、不写外部系统 | ✅ 第一批 | CSV/API adapter、跨源合并、评分规则、报告、大数据量 |
| **B 登录只读** | 浏览器/API 登录后只读采集，人工确认 | 🟡 第二批 | storageState、限速、重试、截图、反爬失败处理 |
| **C 写操作** | 发消息、打招呼、改 Listing、询价、下样品单 | 🔴 第三批/谨慎 | dry_run、confirm_write、额度、幂等、审计、回滚 |

---

## 1. 程序员（Git 工作流）

### 流程拆成插件节点

| 步骤 | 插件能力 | 输入 | 输出 | 量化验收 |
|---|---|---|---|---|
| 1 创建项目 | `repo-bootstrap`（可选） | 仓库名/模板 | README、初始 commit | README 存在，1 个初始 commit |
| 2 拆需求 | `issue-plan` | 需求文档 | Issue 列表（标题/验收标准） | 1 功能=1 Issue，验收标准非空 |
| 3 开发 | `branch-commit-audit` | git log / Issue 号 | 分支-commit 映射 | 1 Issue=1 分支；commit 含 Issue 号 |
| 4 测试 | `ci-status-audit` | CI/PR JSON | test/lint 结果 | test+lint 全绿 |
| 5 提 PR | `pr-create`（写） | 分支/Issue/审查人 | PR 链接 | body 含 `Closes #n`，审查人非空 |
| 6 合并 | `merge-audit` | PR 状态 | 合并记录 | 1 PR=1 次合并，分支已删，Issue 关闭 |

### 推荐插件

1. **`git-flow-audit`（A 类，优先）**：只读本地 git + GitHub/PR JSON，检查“1 功能=1 Issue+1 分支+1 PR+1 合并”、commit 关联、CI 绿。
2. `pr-create`（B/C 类）：需要 GitHub token；写操作，先 dry-run 生成 PR body，再人工确认。

### 需要账号

- GitHub PAT（fine-grained）：仓库 metadata、Actions read；如果要建 Issue/PR，再给 Issues/PR write。
- 不需要密码；token 放环境变量/DPAPI，不入仓库。

### 工厂压测价值

高：状态机（Issue→分支→PR→合并）、API 分页、写操作门禁、审计。

## 2. 招聘人员（BOSS 直聘）

### 流程拆成插件节点

| 步骤 | 插件能力 | 输入 | 输出 | 量化验收 |
|---|---|---|---|---|
| 1 登录 | `boss-session-check` | storageState | 登录态/公司名 | 页面显示公司名 |
| 2 搜索 | `boss-search` | 关键词列表 | 候选人卡片 | 每关键词 ≥50 条 |
| 3 收集 | `boss-collect` | 卡片 | 姓名/岗位/薪资/经验/链接/截图 | 每人有可点击链接 |
| 4 筛选评分 | `boss-score` | 候选人 JSON/CSV | 排名/过滤原因 | 过滤后 ≥原始 30% |
| 5 报告 | `boss-report` | 评分结果 | Markdown/HTML | ≥15 人，含跟进表/Top5 |
| 6 打招呼 | `boss-greet`（写） | Top N | 发送结果 | ≤10 人/次，间隔 ≥30s |

### 推荐插件

1. **`boss-candidate-score`（A 类，优先）**：输入人工导出/粘贴的候选人 CSV，按年龄、薪资、求职状态、领域/技术关键词评分，输出 ≥15 人报告。**不需要账号，先测工厂。**
2. **`boss-candidate-collect`（B 类）**：浏览器只读，登录态由你手动登录后保存 storageState；搜索/滚动/截图/链接采集；限速、失败重试、人工复核。**有 ToS/反爬/个人信息风险，只做只读、低频。**
3. `boss-greet`（C 类）：**不建议先做**；批量打招呼易触发风控/封号，必须 dry-run + 确认 + ≤10 人/30s，且需你明确接受风险。

### 需要账号

- BOSS 招聘者账号；**不要给密码**。推荐：你手动登录一次，提供 `storageState.json`（加密保存、gitignored），或先给导出的 CSV。
- 候选人截图/姓名属个人信息，需限定用途/保留期。

### 工厂压测价值

- A 类：CSV 映射、评分、报告分页。
- B 类：浏览器登录态、滚动加载、限速、截图产物、反爬失败。
- C 类：写闸门/额度/审计（高风险，最后做）。

## 3. 选品人员

### 流程拆成插件节点

| 步骤 | 插件能力 | 输入 | 输出 | 量化验收 |
|---|---|---|---|---|
| 1 打开工具 | `trend-session-check` | 账号/导出 | 可用性 | Google Trends + 选品工具可访问 |
| 2 趋势初筛 | `trend-compare` | 2–3 关键词 | 12 个月曲线/地区 | 2–3 关键词，排除下行/纯季节 |
| 3 类目筛选 | `category-screen` | 月销/价格/评论上限 | 候选 ASIN | 5–10 个候选 |
| 4 逐个核对 | `asin-trend-check` | 5–10 ASIN | 趋势标签 | 向上/平稳/下行 |
| 5 汇总 | `selection-report` | 候选表 | 对比表 | 名称/月销/价格/竞争/趋势/利润 6 字段 |

### 推荐插件

1. **`product-selection-score`（A 类，优先）**：输入 SellerSprite/Sorftime 导出 CSV + Google Trends 导出 CSV，做趋势判断、竞争度、利润粗算、候选排序。**不需要账号。**
2. `trend-fetch`（B 类）：Google Trends 无稳定官方 API，可用 SerpAPI/pytrends；需要接受限流/失败；选品工具需付费账号或导出。
3. `asin-trend-check`（B 类）：Amazon/工具 API 或导出；不建议直接爬。

### 需要账号

- Google Trends：无需登录；若要稳定，可用 SerpAPI（付费 key）。
- 卖家精灵/Sorftime：付费账号；优先给 CSV 导出，其次 API key。
- Amazon SP-API（可选，较复杂）。

### 工厂压测价值

中高：多源 CSV 合并、趋势/利润计算、报告图表/排序；真实 API 接入可放 B 类。

## 4. 跨境运营

### 流程拆成插件节点

| 步骤 | 插件能力 | 输入 | 输出 | 量化验收 |
|---|---|---|---|---|
| 1 登录 | `ops-session-check` | storageState/API | 店铺+17TRACK | 登录态有效 |
| 2 消息 | `ops-message-audit` | 消息导出 | 未回复列表 | 未回复=0 |
| 3 订单 | `ops-order-audit` | 未发货订单 | 处理/异常清单 | 全部处理或标记异常 |
| 4 物流 | `ops-tracking-audit` | 单号列表 | 停滞异常单 | 昨日单号全部查询 |
| 5 Listing | `ops-listing-audit` | Listing 导出 | 改动建议 | 每日改动 ≤3 |
| 6 广告/活动 | `ops-ads-audit` | 搜索词/活动 | 否定词/报名清单 | 高花费零转化词被标记 |

### 推荐插件

1. **`ops-daily-audit`（A 类，优先）**：输入消息/订单/物流/Listing/广告 CSV，输出“未回复、未发货、物流停滞、Listing 改动、否定词”日报。**不需要账号，先测跨源合并。**
2. `ops-tracking-audit`（B 类）：17TRACK/卖家中心只读 API/页面，批量查单号；需要账号/API key。
3. `ops-message-reply` / `ops-listing-edit`（C 类）：真实写操作，必须 dry-run + 人工确认 + 额度；不建议先做。

### 需要账号

- 卖家中心（Shopee/Lazada/TikTok Shop 等）：只读 API key 优先；否则 storageState。
- 17TRACK：API key 或账号。
- 广告后台：只读权限。

### 工厂压测价值

高：多系统合并、SLA、异常分级、日报；B 类可测浏览器/限速；C 类可测写闸门。

## 5. 采购人员

### 流程拆成插件节点

| 步骤 | 插件能力 | 输入 | 输出 | 量化验收 |
|---|---|---|---|---|
| 1 登录 | `1688-session-check` | storageState | 买家账号 | 登录有效 |
| 2 搜索 | `1688-search` | 物料关键词 | 3–5 家商品页 | 供应商 3–5 家 |
| 3 记录 | `supplier-collect` | 商品页 | 单价/MOQ/发货地/样品/评分 | 字段齐全 |
| 4 询价 | `supplier-inquiry`（写） | 供应商列表 | 询价消息 | 每家 ≥1 条 |
| 5 样品 | `sample-order`（写/花钱） | 1–2 家 | 样品单 | 预算内、人工确认 |
| 6 汇总 | `supplier-compare` | 报价 | 比价表 | 6 字段+含税运/交期 |

### 推荐插件

1. **`supplier-quote-compare`（A 类，优先）**：输入 3–5 家报价 CSV（单价/MOQ/运费/税/交期/样品），算 landed cost、交期风险、比价表。**不需要账号。**
2. `1688-search-collect`（B 类）：只读搜索/记录 3–5 家；浏览器登录态、低频；注意平台规则。
3. `supplier-inquiry` / `sample-order`（C 类）：**不建议先做**；涉及真实消息与花钱，必须人工确认、预算上限、审计。

### 需要账号

- 1688 买家账号；建议只读搜索，不要自动发询价/下单。
- 样品预算与审批人；需要你明确授权单笔/单日上限。

### 工厂压测价值

中高：单位/税费/运费计算、比价排序、CSV adapter；C 类可测写闸门/预算。

## 6. 推荐推进顺序（按“压工厂”的价值）

### Wave 1：5 个 A 类插件（无需账号，先做）

| 插件 | 岗位 | 压测点 |
|---|---|---|
| `git-flow-audit` | 程序员 | 本地 git/JSON、流程完整性 |
| `boss-candidate-score` | 招聘 | CSV 映射、评分、≥15 人报告 |
| `product-selection-score` | 选品 | 多源 CSV、趋势/利润、排序 |
| `ops-daily-audit` | 跨境运营 | 多源合并、未回复/未发货/物流异常 |
| `supplier-quote-compare` | 采购 | 税费/运费/landed cost、比价 |

**为什么先做这 5 个**：不需要账号、不触碰外部写操作、可重复跑；能压出 CSV adapter、规则引擎、跨源合并、报告质量、性能问题。

### Wave 2：3 个 B 类只读插件（需要账号/storageState）

| 插件 | 账号 | 风险控制 |
|---|---|---|
| `boss-candidate-collect` | BOSS 招聘者（storageState） | 只读、低频、人工复核、不群发 |
| `ops-tracking-audit` | 卖家中心 + 17TRACK | 只读、批量限速、异常报告 |
| `trend-fetch` | Google Trends/SerpAPI/选品工具 | 限流、失败降级、导出兜底 |

### Wave 3：2 个 C 类写插件（最后，需明确授权）

| 插件 | 写操作 | 必备门禁 |
|---|---|---|
| `boss-greet` | 批量打招呼 | dry-run、confirm、≤10 人/30s、审计 |
| `supplier-inquiry` | 1688 询价/样品 | 人工确认、预算上限、逐条审计 |

---

## 7. 不建议做成“全自动”的部分

- BOSS 批量打招呼/自动索要简历：平台 ToS、封号、个人信息合规风险；建议只做“评分+人工点发送”。
- 1688 自动询价/样品单：涉及真实消息与花钱；必须人工确认、预算上限。
- 卖家中心自动回复/退款/改价：写操作影响真实客户；必须 dry-run + 确认 + 额度。
- Google Trends 高频抓取：不稳定且易限流；优先导出/SerpAPI。
- 截图含个人信息：限定用途、保留期、脱敏。

## 8. 工厂需要补的能力（按 Wave）

- Wave 1：CSV 多文件输入、跨源 join、报告分页/大表、规则配置化。
- Wave 2：storageState 登录态、浏览器限速/重试、截图产物、反爬失败语义。
- Wave 3：写操作 dry-run/confirm/额度/幂等/审计/回滚。
