# 10 · 标准产物契约（dataset.json）

> 背景：批量生产时最容易返工的是"产物形状"。listing-list 首版就因数据集是数组、报告脚本按对象写导致返工。
> 规则：**所有 API 型插件的主产物统一为下面结构**，MCP/Skill/报告只认这一份契约。

## 1. 主产物（`/result` 的 `main`）

```json
{
  "task": "shop_list",
  "fetchedAt": "2026-11-13T10:35:00.000Z",
  "params": { "user_id": 632016, "pages": 2, "pageSize": 100 },
  "extra": { "date_from": "2026-11-01", "date_to": "2026-11-13" },
  "total": 3040,
  "totalPages": 31,
  "pages": [
    { "page": 1, "rows": [ { }, { } ] },
    { "page": 2, "rows": [ { }, { } ] }
  ]
}
```

字段规则：
- `task`：与 MCP `taskType` 一致（`shop_list`/`ads_list`/`listing_list`）。
- `params`：本次实际生效参数（含 pages/pageSize），便于报告写口径。
- `extra`：接口额外元数据（如 ads 的 date_from/date_to），可为空。
- `total/totalPages`：来自 `pagination`；缺失时用样本数兜底并在报告注明。
- `pages[].rows[]`：**原样保留接口行**，不做字段裁剪（报告按需取）。
- 文件名：`<task>_dataset.json`。
- `params` 允许含 `task` 等透传键（MCP 提交体原样进 body）；报告只依赖白名单键（`pages/pageSize/shop_user_name/status/shop_user_id/date_from/date_to`），**不要假设 params 纯净**。

## 2. 执行层写法（强制）

> **`api-runner.js` 位置（2026-11-13 盲测补充）**：放在 `<plugin>/service/api-runner.js`，从 `D:\www\dshspirder\ads-list\service\api-runner.js` 复制。
> ⚠️ `listing-list` 是 v0 直连实现（fetcher 里直接 fetch），**不要抄它**；抄 `ads-list` / `shop-list`。
>
> `runTask(job, ctx, taskConfig)` 的 taskConfig 字段：
>
> | 字段 | 必填 | 说明 |
> |---|---|---|
> | `task` | ✅ | 与 taskType 一致，写入 dataset.task |
> | `path` | ✅ | 接口路径（相对 baseUrl） |
> | `authEnv` | ✅ | 凭证环境变量名（如 `LISTING_API_KEY`） |
> | `pageSize` | ✅ | 单页条数（受接口上限约束） |
> | `maxPages` | ✅ | 页数上限（防误拉全量） |
> | `buildBody` | ✅ | `(params, page, pageSize) => body` |

```js
// fetcher.js 只写配置，逻辑全部走 api-runner
const { runTask } = require('./api-runner');
const TASK = {
  task: 'shop_list',
  path: '/agent/shopee/user/openapi/shop/list',
  authEnv: 'LISTING_API_KEY',
  pageSize: 100,
  maxPages: 10,
  buildBody: (p, page, pageSize) => ({ user_id: Number(p.user_id) || 632016, page, pageSize }),
};
async function runJob(job, ctx) { return runTask(job, ctx, TASK); }
```

### 3.1 报告脚本如何找到数据集（强制，2026-11-13 盲测补充）

产物在 `service/data/jobs/<jobId>/<task>_dataset.json`，**不要要求业务人员手工复制**。报告脚本必须支持三级回退（参考实现 `factory-kit/dataset.mjs`）：

- 报告页眉必须写「任务：<jobId> / 取数时间：<fetchedAt>」，否则业务人员无法判断是不是新数据；
- 报告脚本入参：`node gen-report.mjs [dataset.json 路径]`，不传则自动取最新 job。

```js
// 1) 命令行参数：node gen-report.mjs <dataset.json>
// 2) 自动取最新 job 的产物
// 3) 兼容旧的手工复制路径 data/dataset.json
async function resolveDataset(fallbackDir) {
  const arg = process.argv[2];
  if (arg) return JSON.parse(await readFile(arg, 'utf8'));
  const jobsDir = path.join(fallbackDir, 'service', 'data', 'jobs');
  try {
    const dirs = (await readdir(jobsDir)).sort().reverse();
    for (const d of dirs) {
      const files = await readdir(path.join(jobsDir, d)).catch(() => []);
      const f = files.find((x) => x.endsWith('_dataset.json'));
      if (f) return JSON.parse(await readFile(path.join(jobsDir, d, f), 'utf8'));
    }
  } catch {}
  return JSON.parse(await readFile(path.join(fallbackDir, 'data', 'dataset.json'), 'utf8'));
}
```

### 3.2 清理/处置类业务的双层口径（盲测教训）

「可清理」不能只用"缺图/缺价/重复"这类字段缺失判定——实测 40 条草稿字段全部齐备，硬规则命中 0，但实际积压 122 天。
规则：**硬清理规则（缺失/违规）** + **归档候选规则（长期未动销/从未上架/长期未更新）** 两层分别统计，报告分开写，结论不能只写"无需清理"。

## 5. 空数据规则（2026-11-13 边界测试补充）

接口返回 `rows=[]`（`total=0`）时：
- 服务层：任务仍为 `done`（"查到了，就是没有"），数据集 `pages=[]`、`total=0`；
- 报告层：**必须拒绝生成并退出码 2**，打印 `[SKIP] 数据集为空…`，**不得覆盖上一份正常报告**；
- Skill 层：向用户说明"该参数/周期无数据"，不输出结论与建议。

参考实现（3 个报告生成器已加守卫）：

```js
if (!rows.length) { console.error('[SKIP] 数据集为空（0 条）：不生成报告，保留旧报告。'); process.exit(2); }
```

## 6. 错误透传规则（边界测试）

接口业务错误（如 `code=100400`）必须变成**可读的失败原因**，不得静默成空数据：
`接口业务失败 code=100400：date time.0 与给定的格式 Y-m-d 不符合` ← 来自 ads-list 实测。
