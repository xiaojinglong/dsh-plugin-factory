# 46 — 插件输出模型：报告只是可选产物

> 纠正定位：插件工厂不是“报告生成器”，而是“把业务流程封装成可被 AI 调用的业务动作”。
> 报告只是查询/分析类插件的一种产物；写操作/消息/文件类插件不需要 HTML 报告。

## 1. 插件不是报告

| 插件类型 | 典型输出 | 报告是否必需 |
|---|---|---|
| 查询/分析 | 数据集、指标、HTML/Markdown 报告 | 可选 |
| 写 API | 变更条数、失败列表、回执、审计 | 可选 |
| 状态标记 | 状态流转记录、失败/跳过原因 | 通常不需要 |
| 修改 Excel/文件 | 新文件、diff、校验结果 | 可选 |
| 发消息/通知 | 发送回执、重试记录、失败原因 | 通常不需要 |
| 混合动作 | 以上组合 + 人工确认 | 可选 |

**统一必须有的是“执行证据/审计”**：做了什么、对谁做、成功/失败、能否回滚；
HTML 报告只是证据的一种展示形式。

## 2. 当前工厂的偏差

当前模板和校验仍然偏向“报告型”：

- 生成器默认创建 `gen-report.mjs`
- `validate` 的 staging 检查包含 `staging:report`
- 插件 manifest 默认有 `report` 字段
- 28 个现有插件都有报告，容易让人误以为“插件=报告”

这不影响现有查询类插件，但会限制动作类插件的表达。

## 3. 目标输出契约（建议）

每个插件在 `plugin.json`/manifest 声明：

```json
{
  "effect": "read | write | message | file | mixed",
  "outputs": ["dataset", "audit", "report?", "file?", "receipt?"],
  "confirmWrite": true,
  "idempotency": "required | optional | none",
  "rollback": "supported | manual | none"
}
```

运行时统一返回：

```json
{
  "status": "done",
  "effects": [{ "target": "...", "action": "...", "ok": true }],
  "artifacts": [{ "kind": "dataset|report|file|receipt", "path": "..." }],
  "audit": { "actor": "...", "confirm": true, "idempotencyKey": "..." },
  "error": null
}
```

报告只是 `artifacts` 里 `kind=report` 的一项，可为空。

## 4. 四种动作插件示例

### 4.1 更新 API 数据

- 输入：订单/库存 JSON
- 动作：调用 API 更新字段
- 输出：`updated=10, failed=2`、失败原因、审计
- 报告：可选（给业务看汇总）

### 4.2 标记状态

- 输入：待处理列表
- 动作：批量标记“已处理/异常”
- 输出：状态流转记录、跳过原因
- 报告：通常不需要

### 4.3 修改 Excel

- 输入：原文件 + 修改规则
- 动作：写新文件，原文件不动
- 输出：新文件路径 + cell diff + 校验结果
- 报告：可选（附 diff 摘要）

### 4.4 发消息

- 输入：收件人/模板/变量
- 动作：发送（写操作，需 confirm + 额度 + 幂等）
- 输出：每条发送回执、重试、失败原因
- 报告：通常不需要

## 5. 工厂需要改什么

1. `effect/outputs` 契约进入 manifest 和生成器。
2. `report` 改为可选；validate 按 `outputs` 校验，不强制 HTML。
3. `ctx` 增加 `emitArtifact/recordEffect`；runner 可只返回 effects。
4. `plugin-install`/MCP/DSH skill 展示“变更结果”，不只给报告链接。
5. 写操作默认：dry_run → confirm_write → 额度 → 幂等 → 审计 → 回滚。
6. 现有 28 个报告型插件保留；新增动作型插件不强行套报告模板。

## 6. 优先级

- **P0**：manifest 增加 `effect/outputs`；报告可选；1 个“标记状态”或“改 Excel”样板。
- **P1**：写操作统一 effects/audit/rollback；消息类 outbox。
- **P2**：动作型插件纳入场景矩阵和工厂回归。

> 结论：把“插件=报告”改成“插件=业务动作，报告是可选证据”，这是产品定位修正，不是功能小补丁。

> **P0 已落地**：`excel-status-mark` 无报告动作插件已跑通 pipeline/install/job，生成新 xlsx + 审计；详见 `docs/47`。
