# 73 · 爬虫型插件双交付强制标准

> 本文件是强制要求，优先于一般插件交付流程。
>
> 适用范围：任何需要浏览器、登录、扫码、页面点击、页面采集、文件下载的插件需求。

## 1. 项目目标（不可偏离）

> 让不会写代码的业务人员，用自然语言把工作流程变成**可安装、可调用**的 DSH 插件。

用户不应该看到：

- 函数名
- 参数名
- jobId
- 代码块
- Playwright / 浏览器操作细节

用户只应该用自然语言：

```text
把标准库第一条产品认领到 Mercado
现在进度多少
扫码完成，继续
导出结果
```

## 2. 双交付物

凡涉及爬虫/浏览器自动化，必须交付**两个独立物**：

```text
1. 独立爬虫服务
2. 标准 DSH 薄插件
```

不允许把两者合并成一个插件。

## 3. 独立爬虫服务标准

服务可以放在 `dshspirder`，也可以单独建项目；目录名不限，但必须遵守 `dshspirder` 规范。

### 3.1 固定结构

```text
<service-dir>/
├── package.json
├── .env
├── .gitignore
├── src/
│   ├── server.js      HTTP 接入层
│   ├── job.js         队列 / 状态机 / 单 worker
│   ├── crawler.js     页面流程与选择器（唯一耦合页面的文件）
│   └── util.js
└── data/
    ├── jobs/<jobId>/
    └── sessions/
```

### 3.2 技术栈

```text
Node.js + Fastify + Playwright
```

### 3.3 固定 HTTP 契约

```text
POST /jobs                 提交任务，立即返回 { jobId, status }
GET  /jobs/:jobId          轻量状态 { jobId, status, progress, error }
GET  /jobs/:jobId/verify   仅 waiting_verify，返回二维码/验证码图片
POST /jobs/:jobId/verify   提交验证码或人工放行
GET  /jobs/:jobId/result   仅 done，返回主文件/明细/缺失项
GET  /health               健康检查 { ok: true }
```

状态枚举固定：

```text
queued → waiting_verify → running → done / failed
```

### 3.4 强制约束

- 全局单 worker，任务排队
- 异步执行，HTTP 不阻塞
- 禁止固定 sleep，使用元素/网络/表格加载断言
- 页面选择器只允许出现在 `crawler.js`
- 登录态持久化到 `data/sessions`
- 产物落 `data/jobs/<jobId>`，当场绑定业务名称到 `meta.json`
- 单任务失败不影响 HTTP 服务
- 失败保留截图和可读错误
- 对外可独立 `curl` 自测
- 可独立启动、换端口、换机器
- 未来换官方 API 时，主要只改 `crawler.js`，接口契约不变

### 3.5 登录态缓存强制标准

登录型服务必须默认实现以下内容，不需要用户每次提醒：

- 使用持久化 Chrome profile，并保存 `storageState`/cookies 到 `data/sessions/`
- 新任务启动时**显式注入**登录态；不能只依赖启动参数
- 只有确认登录成功后才写回登录态
- **登录失败、登录超时、任务失败时绝不能覆盖已有有效缓存**
- 每次启动先校验会话；只有会话无效时才进入 `waiting_verify`
- 连续任务必须复用会话，不能要求用户重复扫码
- 会话文件可随服务迁移；凭证/缓存不提交仓库
- 测试必须包含：
  - 第一次登录成功
  - 第二次任务无需登录
  - 强制登录失败不破坏已有缓存

## 4. DSH 薄插件标准

### 4.1 标准 bundle 结构

```text
package.json          dsh.bundle.patch
cordis.patch.yml
index.js              export function apply(ctx)
locale/
icon.svg
skills/
```

必须能通过标准方式安装到 DSH profile。

### 4.2 插件只允许做

- HTTP 调用独立服务
- 参数校验
- 状态/结果展示
- 注册 DSH Tool / Skill
- 自然语言话术

### 4.3 插件禁止包含

```text
playwright
chromium
browser context
Chrome profile
页面选择器
扫码/验证码逻辑
爬虫代码
```

### 4.4 工具必须异步

推荐工具：

```text
<业务>_start    提交任务，立即返回
<业务>_status   查询进度
<业务>_verify   获取/提交验证码
<业务>_result   获取结果
```

禁止：

```text
一个工具同步等登录 300 秒
一个工具在 DSH sandbox 里启动浏览器
一个工具超过 30 秒不返回
```

## 5. 连接方式

插件只通过 HTTP 连接服务：

```text
serviceBaseUrl = http://127.0.0.1:<port>
```

插件不保存浏览器登录态；登录态由服务管理。

## 6. 迁移要求

### 6.1 服务迁移

```text
复制服务目录
npm install
npx playwright install chromium
配置 .env
npm start
```

需要迁移：

- `src/`
- `package.json`
- `.env`（按目标机改端口）
- 按需迁移 `data/sessions`
- 按需迁移 `data/jobs`

### 6.2 插件迁移

```text
复制插件 zip
标准安装
修改 serviceBaseUrl
重启 DSH
```

插件不得依赖：

- 本机 Chrome
- `dshspirder` 的绝对路径
- 浏览器 profile
- 服务端源码路径

## 7. 强制门禁

### 门禁 A：先服务，后插件

```text
服务未独立启动 / curl 未通过
→ 禁止生成插件
```

### 门禁 B：插件不得含浏览器代码

```text
发现 playwright / chromium / selector / browser profile
→ 直接判失败，退回重构
```

### 门禁 C：异步

```text
工具超过 30 秒同步阻塞
→ 判失败
```

### 门禁 D：自然语言

```text
用户需要写参数、jobId、代码
→ 判失败
```

### 门禁 E：可迁移

```text
服务换端口后插件不能只改配置适配
或插件换机器必须带浏览器代码
→ 判失败
```

### 门禁 F：不能分离就不做

```text
无法拆成独立服务 + 薄插件
→ 停止，不写插件
```

## 8. 交付验收清单

```text
[ ] 服务能独立启动
[ ] 服务 /health 通过
[ ] 服务 POST /jobs 立即返回
[ ] 服务状态/verify/result 完整
[ ] 服务单 worker、排队、异常隔离
[ ] 服务选择器只在 crawler.js
[ ] 服务登录态可持久化
[ ] 新任务显式注入登录态
[ ] 登录失败不会覆盖缓存
[ ] 第二次任务无需重复登录
[ ] 插件不含 Playwright/浏览器/选择器
[ ] 插件只调用 HTTP
[ ] 插件工具异步，30 秒内返回
[ ] 插件标准安装成功
[ ] 用户全程自然语言
[ ] 服务换端口只改插件配置
[ ] 插件换机器不带浏览器代码
```

## 10. 结论

违反本文件任何一条，不得称为“标准 DSH 插件交付”。

特别是：

> 插件里出现 Playwright、浏览器、页面选择器，直接判不合规。  
> 无法拆成独立服务 + 薄插件，直接停止，不写插件。
