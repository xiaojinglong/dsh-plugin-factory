# 73 · 爬虫型插件双交付强制标准

> 本文件是强制要求，优先于一般插件交付流程。
>
> 适用范围：任何需要浏览器、登录、扫码、页面点击、页面采集、文件下载的插件需求。

## 1. 项目目标（不可偏离）

> 让不会写代码的业务人员，用自然语言把工作流程变成**可安装、可调用**的 DSH 插件。

用户不应该看到：

- 函数名
- 参数名
- jobId
- 代码块
- Playwright / 浏览器操作细节

用户只应该用自然语言：

```text
把标准库第一条产品认领到 Mercado
现在进度多少
扫码完成，继续
导出结果
```

## 2. 双交付物

凡涉及爬虫/浏览器自动化，必须交付**两个独立物**：

```text
1. 独立爬虫服务
2. 标准 DSH 薄插件
```

不允许把两者合并成一个插件。

## 3. 独立爬虫服务标准

服务可以放在 `dshspirder`，也可以单独建项目；目录名不限，但必须遵守 `dshspirder` 规范。

### 3.1 固定结构

```text
<service-dir>/
├── package.json
├── .env
├── .gitignore
├── src/
│   ├── server.js      HTTP 接入层
│   ├── job.js         队列 / 状态机 / 单 worker
│   ├── crawler.js     页面流程与选择器（唯一耦合页面的文件）
│   └── util.js
└── data/
    ├── jobs/<jobId>/
    └── sessions/
```

### 3.2 技术栈

```text
Node.js + Fastify + Playwright
```

### 3.3 固定 HTTP 契约

```text
POST /jobs                 提交任务，立即返回 { jobId, status }
GET  /jobs/:jobId          轻量状态 { jobId, status, progress, error }
GET  /jobs/:jobId/verify   仅 waiting_verify，返回二维码/验证码图片
POST /jobs/:jobId/verify   提交验证码或人工放行
GET  /jobs/:jobId/result   仅 done，返回主文件/明细/缺失项
GET  /health               健康检查 { ok: true }
```

状态枚举固定：

```text
queued → waiting_verify → running → done / failed
```

### 3.4 强制约束

- 全局单 worker，任务排队
- 异步执行，HTTP 不阻塞
- 禁止固定 sleep，使用元素/网络/表格加载断言
- 页面选择器只允许出现在 `crawler.js`
- 登录态持久化到 `data/sessions`
- 产物落 `data/jobs/<jobId>`，当场绑定业务名称到 `meta.json`
- 单任务失败不影响 HTTP 服务
- 失败保留截图和可读错误
- 对外可独立 `curl` 自测
- 可独立启动、换端口、换机器
- 未来换官方 API 时，主要只改 `crawler.js`，接口契约不变

### 3.5 登录态缓存强制标准

登录型服务必须默认实现以下内容，不需要用户每次提醒：

- 使用持久化 Chrome profile，并保存 `storageState`/cookies 到 `data/sessions/`
- 新任务启动时**显式注入**登录态；不能只依赖启动参数
- 只有确认登录成功后才写回登录态
- **登录失败、登录超时、任务失败时绝不能覆盖已有有效缓存**
- 每次启动先校验会话；只有会话无效时才进入 `waiting_verify`
- 连续任务必须复用会话，不能要求用户重复扫码
- 会话文件可随服务迁移；凭证/缓存不提交仓库
- 测试必须包含：
  - 第一次登录成功
  - 第二次任务无需登录
  - 强制登录失败不破坏已有缓存

## 4. DSH 薄插件标准

### 4.1 标准 bundle 结构

```text
package.json          dsh.bundle.patch
cordis.patch.yml
index.js              export function apply(ctx)
locale/
icon.svg
skills/
```

必须能通过标准方式安装到 DSH profile。

### 4.2 插件只允许做

- HTTP 调用独立服务
- 参数校验
- 状态/结果展示
- 注册 DSH Tool / Skill
- 自然语言话术

### 4.3 插件禁止包含

```text
playwright
chromium
browser context
Chrome profile
页面选择器
扫码/验证码逻辑
爬虫代码
```

### 4.4 工具必须异步

推荐工具：

```text
<业务>_start    提交任务，立即返回
<业务>_status   查询进度
<业务>_verify   获取/提交验证码
<业务>_result   获取结果
```

禁止：

```text
一个工具同步等登录 300 秒
一个工具在 DSH sandbox 里启动浏览器
一个工具超过 30 秒不返回
```

## 5. 连接方式

插件只通过 HTTP 连接服务：

```text
serviceBaseUrl = http://127.0.0.1:<port>
```

插件不保存浏览器登录态；登录态由服务管理。

## 6. 迁移要求

### 6.1 服务迁移

```text
复制服务目录
npm install
npx playwright install chromium
配置 .env
npm start
```

需要迁移：

- `src/`
- `package.json`
- `.env`（按目标机改端口）
- 按需迁移 `data/sessions`
- 按需迁移 `data/jobs`

### 6.2 插件迁移

```text
复制插件 zip
标准安装
修改 serviceBaseUrl
重启 DSH
```

插件不得依赖：

- 本机 Chrome
- `dshspirder` 的绝对路径
- 浏览器 profile
- 服务端源码路径

## 7. 强制门禁

### 门禁 A：先服务，后插件

```text
服务未独立启动 / curl 未通过
→ 禁止生成插件
```

### 门禁 B：插件不得含浏览器代码

```text
发现 playwright / chromium / selector / browser profile
→ 直接判失败，退回重构
```

### 门禁 C：异步

```text
工具超过 30 秒同步阻塞
→ 判失败
```

### 门禁 D：自然语言

```text
用户需要写参数、jobId、代码
→ 判失败
```

### 门禁 E：可迁移

```text
服务换端口后插件不能只改配置适配
或插件换机器必须带浏览器代码
→ 判失败
```

### 门禁 F：不能分离就不做

```text
无法拆成独立服务 + 薄插件
→ 停止，不写插件
```

```text
[ ] 服务选择器只在 crawler.js
[ ] 服务登录态可持久化
[ ] 新任务显式注入登录态
[ ] 登录失败不会覆盖缓存
[ ] 第二次任务无需重复登录
[ ] 插件不含 Playwright/浏览器/选择器
[ ] 插件只调用 HTTP
[ ] 插件工具异步，30 秒内返回
[ ] 插件标准安装成功
[ ] 用户全程自然语言
[ ] 服务换端口只改插件配置
[ ] 插件换机器不带浏览器代码
[ ] 无反检测/指纹伪造/代理轮换代码
```


## 11. 爬虫开发实战坑清单（强制）

以下都是实际项目踩过的坑，后续爬虫服务必须逐项检查。

### 11.1 架构与插件

| 坑 | 强制规则 |
|---|---|
| 把 Playwright 写进插件 | 爬虫代码只能在独立服务；插件只发 HTTP |
| 插件同步等登录 300 秒 | 插件 start 立即返回；status/verify/result 异步 |
| 直接跑 `impl.js` 后说插件成功 | 必须通过已安装的 DSH Tool 验收，不能绕过插件 |

### 11.2 登录态与会话

| 坑 | 强制规则 |
|---|---|
| 只保存 `auth.json`，启动不注入 | 启动后显式 `context.addCookies(auth.cookies)`，不能只传 `storageState` |
| 登录失败/超时也写回缓存 | 只有 `loggedIn=true` 才写回；失败绝不覆盖有效缓存 |
| 每次任务都要求重新扫码 | 连续任务必须复用会话；必须做“第二次任务免登录”测试 |
| 把登录页账号输入框误判成搜索框 | 登录检测必须看 URL/登录页特征/特定搜索控件，不能用通用 `input[type=text]` |

### 11.3 页面与控件

| 坑 | 强制规则 |
|---|---|
| 1688 搜索框不是 `input` | 真实控件是 `textarea#alisearch-input`；必须按站点的真实 DOM 适配 |
| 表单 `target=_blank` 开新标签 | 提交后接管新 page，不能继续操作旧首页 |
| 只把关键词填进输入框，没点搜索 | 必须点击真实搜索按钮，并断言结果页商品卡出现 |
| 把首页推荐商品当成搜索结果 | 必须校验当前 URL 是搜索页，不能用首页数据冒充搜索数据 |

### 11.4 编码（1688 重点）

| 坑 | 强制规则 |
|---|---|
| 1688 搜索使用 GBK | 用 `iconv-lite` 将关键词编码为 GBK 字节，再拼 `%XX` |
| `new URL()` / `URLSearchParams` 重编码 GBK | 禁止用 URL 对象处理 GBK 查询；会变成 `%EF%BF%BD`，关键词显示 `圣锟斤拷...` |
| 复用浏览器回写 URL 翻页 | 翻页必须用服务端保存的 canonical URL，不能读 `page.url()` 再拼 |
| 中文文件名写成 `???` | Excel 文件名用 ASCII jobId；关键词放 metadata/结果字段 |
| 只验证第一页 URL | 必须检查第 2/3 页 URL 仍包含正确 GBK 编码 |

### 11.5 分页与抓取

| 坑 | 强制规则 |
|---|---|
| 以为所有站点都有“下一页”按钮 | 1688 用 `beginPage`；必须按站点分页机制实现 |
| 只抓详情链接导致漏卡 | 优先用稳定商品卡选择器（1688：`.offer-card-container`），详情链接只做兜底 |
| 页面没加载就找卡片 | 必须 `waitFor` 商品卡/表格出现，不能固定 sleep 后直接取 |
| 空页直接标记成功 | 空页写入 `missingPages`；可重试，但不能伪造 |
| 风控/滑块当普通空白 | 必须识别验证文本，进入 `waiting_verify`，人工完成后继续 |

### 11.6 成功判定

| 坑 | 强制规则 |
|---|---|
| 弹窗关闭 = 成功 | 关闭只代表流程推进；必须有成功文案或页面状态断言 |
| 按钮 disabled 仍硬点 | 点击前检查按钮 enabled、页面校验错误；否则失败/暂停 |
| 页面提示“标题重复，请修改”仍说 done | 业务校验失败必须 `failed` 或 `waiting_verify`，不能假成功 |
| 缺页仍返回 pagesDone=请求页数 | 用实际成功页数，缺页进 `missingPages` |

### 11.7 诊断与测试

| 坑 | 强制规则 |
|---|---|
| 失败只有一句“页面结构变化” | 必须保存 failure 截图、当前 URL、调试 HTML |
| 只测 1 页就上 10 页 | 至少 1 → 3 → 10 页逐级验证 |
| 不检查关键词编码 | 每级测试都检查搜索 URL 和搜索框关键词 |
| 不检查字段完整性 | 验证标题/价格/起批量/销量/店铺/链接/页码 |
| 不检查缺页 | 结果必须含 `missingPages`，Excel 可打开 |
| 反复重试触发风控 | 空页/验证要暂停或降频，不能无限硬刷 |

### 11.8 目标一致性（爬虫专项）

爬虫服务必须证明“抓到的就是目标”，不能只证明“代码能跑”。

必须对照：

| 目标 | 必须验证 |
|---|---|
| 目标 URL | 实际 URL 是目标搜索/列表页，不是首页推荐 |
| 关键词 | 搜索框和 URL 编码正确（如 GBK） |
| 页数 | 实际完成页数、缺页列表 |
| 商品 | 标题/价格/起批量/销量/店铺/链接 |
| 成功标志 | 页面成功文案或数据状态，不是弹窗关闭 |
| 登录 | 缓存复用；失效才 waiting_verify |
| 验证码/滑块 | waiting_verify，人工完成，不绕过 |
| 输出 | Excel 可打开、行数、字段、缺页可追溯 |

强制流程：

```text
目标契约
→ tests/target-conformance.test.mjs
→ 真实目标 1/3/10 页
→ expected / actual / diff
→ 修服务/编码/选择器/分页
→ 重跑，最多 3 轮
→ 仍不一致：停止交付
```

禁止：

- 改测试让失败变通过
- 用 fixture 代替真实目标
- 只测 1 页就宣称 10 页
- 缺页仍写“完成”
- 目标 URL/关键词不一致仍发布

### 11.9 凭证与权限审计

插件源码不得包含明文密钥：

- API key / token / password / 私钥
- `Bearer` 长字符串
- 写死的凭据值

只允许 `spec.credentials` 声明环境变量名，例如：

```json
{ "env": "SPIRDER_1688_SERVICE_URL", "required": false }
```

权限审计：

- `filesystem` 只允许 `read` / `write`
- `network` 只写 host（如 `127.0.0.1`），不能写 URL/路径
- `process` 默认关闭
- 发现明文密钥或非法权限声明，直接判失败

## 12. 反规避与合规红线

爬虫服务的目标是**稳定、合法地完成授权业务**，不是“降低被检测概率”。

### 12.1 禁止写入实现

- 抹平 `navigator.webdriver`
- 伪造/随机化浏览器指纹（UA、Canvas、WebGL、屏幕、时区、语言）
- `playwright-stealth` 或同类反检测插件
- 代理池/住宅代理轮换以规避封禁
- 验证码识别、滑块自动破解
- TLS/JA3 伪造、请求签名逆向
- 随机鼠标轨迹、随机等待等**以规避检测为目的**的行为伪装

### 12.2 允许的稳定性措施

- 使用真实安装的 Chrome，可见窗口完成登录
- 用户扫码/人工验证
- 持久化会话，复用登录态
- 单 worker、队列、限速、退避
- 元素加载断言，不固定 sleep
- 失败截图、缺页记录、可重试
- 遇到验证码/滑块进入 `waiting_verify`，人工完成后继续
- 使用官方 API、企业版导出或授权数据接口

### 12.3 判定原则

```text
如果做法的主要目的是“让平台认为我是人”
→ 不做

如果做法的主要目的是“少打扰、可恢复、可审计”
→ 可以做
```

被目标站拦截时：

```text
暂停 → 人工验证 → 降低频率 → 官方接口
不得绕过
```

## 13. 结论

违反本文件任何一条，不得称为“标准 DSH 插件交付”。

特别是：

> 插件里出现 Playwright、浏览器、页面选择器，直接判不合规。  
> 无法拆成独立服务 + 薄插件，直接停止，不写插件。
