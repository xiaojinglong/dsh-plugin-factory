# 26 — M5 分发与升级（A 单机版）

> 状态：M5 ~25%（发布包 + 校验 + CI 工作流已具备；分发渠道/签名/升级策略待 owner 决策）。
> 本文是策略与操作说明，不冒充已发布到公网。

## 1. 分发形态

| 形态 | 适用 | 状态 |
|---|---|---|
| GitHub Release（私有仓库 → 指定人） | 团队内部/试点 | 工作流已就绪，待打 tag 验证 |
| npm tarball（`npm pack`） | 离线/内网分发 | ✅ `release:package` 产出 |
| 直接克隆仓库 | 开发者 | ✅ |
| 安装器 exe/签名包 | 非技术业务人员 | ⏳ 需 owner 签名证书 |

## 2. 版本与兼容

- 工厂版本：根 `package.json` `version`（当前 3.2.0）。
- 插件声明 `runtimeRange`（如 `^3.2`）；`plugin-install preflight` 会比对工厂版本，不兼容直接拒绝安装。
- 升级：`plugin-install upgrade --source <new>` 只允许更高版本；`--force` 可降级/重装，旧目录与 manifest 自动备份。
- 回滚：`uninstall` 恢复备份；生产升级前先 `backup_state`（控制面）并保留旧 staging。

## 3. 发布流程（owner/CI）

```powershell
npm ci
npm run check
npm test
npm run release:package -- --out dist
node scripts/verify-release.cjs --out dist
# 产物：dist/*.tgz + dist/release.json（sha256/commit/文件数）
```

- CI：`.github/workflows/release.yml`（tag `v*` 触发，测试→打包→校验→上传 artifact）。
- 签名：需要 owner GPG/代码签名证书；未配置前 release.json 只提供 SHA-256，不声称“已签名”。
- 敏感路径：打包脚本拦截 `.env`（模板除外）、`platform/secrets`、`data/`、`*.db`、control-plane token。

## 4. 升级策略

1. 先在临时工厂根 `preflight` + `--dry-run`。
2. `install --render`（smoke + render）；失败自动回滚。
3. 生产升级：备份 control-plane + 旧插件目录 → `upgrade` → `verify` → 冒烟。
4. 回滚：`uninstall`（恢复备份）/ 还原 control-plane 备份。
