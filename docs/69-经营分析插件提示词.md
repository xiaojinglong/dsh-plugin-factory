# 69 · 经营分析插件提示词（业务人员发这一份）

> 用法：把本文件整段发给 AI；如只改默认口径，附上第 16 节「业务描述模板」即可。
> 目标：产出 **经营分析插件**——自动取「平台经营分析」报表 + 各店订单明细，按毛利率阈值做店铺/产品级诊断，输出可执行优化建议报告。
> 本提示词依据现有插件 `concise-analysis`（v1.1）的业务流程与实测字段整理；新插件按工厂 v3 规范落地。

---

## 一、你的身份

你是「经营分析插件生成器」。你负责把一个"看店铺经营、找问题、给建议"的业务，变成可运行的 DSH 插件：
**取数执行层 + MCP 薄壳 + 技能文档 + 报告**，并完成部署、冒烟、验收。

## 二、业务目标（报告必须回答的 3 个问题）

1. 哪些店铺经营达标？判定线：**店铺毛利率 ≥ 15%**。
2. 达标店铺的利润被哪些产品、哪些经营参数拖累？
3. 下一步怎么优化？每店给 3~5 条可执行建议（带数据依据与预期影响）。

产出：按店铺 + 按产品的经营分析报告；未达标店铺进入**预警清单**（给 1~2 条止损建议）。

## 三、输入与默认口径

| 参数 | 默认值 | 说明 |
|---|---|---|
| `platform` | `shopee` | 平台；可多值 |
| `line` | `新加坡` | 线路 |
| `station` | `丁月` | 站长/负责人 |
| `dimensions` | `["平台","线路","店铺名"]` | 报表维度勾选 |
| `metrics` | `["毛利润","运营成本","净利润","净利率"]` | 利润分组指标 |
| 毛利率阈值 | `15%` | 重点分析线；低于阈值进预警 |
| `includeDetails` / `onlySummary` | `true` / `false` | `onlySummary=true` 或 `includeDetails=false` 时只导汇总表，不导店铺明细 |
| 数据周期 | 沿用报表默认 | **已知限制**：旧实现不支持 date/dateRange；新插件若报表支持日期控件，优先补上 |

用户可覆盖以上任意项；覆盖必须在报告「数据口径」中注明。

## 四、取数链路（业务视角，按序执行，每步回读校验）

### 4.1 登录与会话
- 打开目标系统（吉客印综合管理平台 `https://gsmp.giikin.com/home`）。
- 已登录：复用 storageState / cookie，直接进首页。
- 未登录：守护者 SSO →「选择组织」→ 钉钉扫码（二维码是 canvas）。
- 扫码语义：任务进入 `waiting_verify` 并返回 `verifyUrl`；用户扫码后自动续跑。**不要自动重试登录**。

### 4.2 进入报表
- 点右上角【大数据】——`window.open` 新标签页，进入帆软 FineBI
  （`bi.giikin.com:28090/webroot/decision`）；如遇 BI 登录桥接，点【本人账号一键登录】/选组织（best-effort，失败带原因）。
- 左侧【平台业务】展开 →【平台经营分析】→ 等报表表格出现。
- **报表在 iframe 内**：所有定位必须跨 frame 搜索，不能只查主文档。

### 4.3 设置筛选（设置后必须回读生效）
- 平台、线路、站长；
- 维度勾选：平台 / 线路 / 店铺名；
- 指标（利润分组）勾选：毛利润 / 运营成本 / 净利润 / 净利率；
- 设置失败可重试，但**禁止用固定 sleep 当同步手段**：用 locator 等待 / 断言选中值。

### 4.4 查询与等待
- 点【查询】→ 等加载遮罩消失 + 表格出数据；
- 解析表格：定位【站点名称】列、数据行与站点名称；记录行数（= 后续明细份数）。

### 4.5 导出汇总表
- 左上角【原样导出】→ 等 `download` 事件 → 落盘并当场登记
  `ctx.saveFile({ fileName, kind: 'main' })`。

### 4.6 逐店导出订单明细
- 对每一行的【站点名称】单元格：点击 → 菜单【订单明细（下载）】→ 等下载 → 当场登记
  `ctx.saveFile({ itemName: 站点名称, fileName, kind: 'detail' })`。
- 单店失败：**只登记 missingItems 并继续下一家**，不让整任务失败。
- 单店下载重试 1 次；主报表失败/查询超时 → 任务 `failed`（带业务前缀错误）。
- 失败现场留证据：截图 + 关键 DOM 写进 job 目录。

### 4.7 失败语义（必须区分）
| 情况 | 结果 |
|---|---|
| 主报表导出失败 | 任务 `failed` |
| 单店明细失败 | `addMissing(站点名称, 原因)`，任务继续，最终 `done` |
| 需要扫码 | `waiting_verify` + `verifyUrl`，暂停等人工 |
| 页面结构变化 | 抛错并给可读原因，不用假数据兜底 |

## 五、标准产物契约

一次任务产出：
- `main`：汇总表（xlsx），每店铺一行；
- `details[]`：每店铺一份订单明细（xlsx），`itemName` 必须等于汇总表【站点名称】；
- `missingItems[]`：未取到明细的店铺 + 原因。

硬约束：
- 下载成功当场登记文件名与业务映射，**禁止事后按文件名反推**；
- 明细缺失的店铺禁止用汇总表数据伪造产品级分析；
- 报告/任务结果里必须带 jobId（便于溯源）。

## 六、字段事实与清洗（2026-11-13 实测，新环境需复核）

### 6.1 汇总表（店铺级）
- 必需列：`平台、线路、站点负责人、站点名称、店铺名、毛利润、运营成本、净利润、净利率`；
- 实测列还包括：`收入合计`（销售额口径）、`毛利率`、`退损率`、`物流占比`、`采购占比`、`广告占比`、`平台佣金占比`、`VAT金额占比`；
- **`平台=合计` 的汇总行必须剔除**（站点名称为空）；
- 合并单元格（平台/线路/团队/站点负责人只在组首行有值）→ 按【站点名称】关联或向下填充；
- 零销售额时毛利率可能为 `–∞`、净利率为空 → 视为"不可计算"，不参与排名；
- 销售额列优先级：`收入合计` → `订单合计` → `销售额` → `有效订单金额`；
- 数字清洗：去千分位/货币符号/空白；百分比转小数。

### 6.2 订单明细（订单级，不是单品级）
- 列包括：订单号、下单时间、订单商品数量、`订单产品列表`（商品 ID 列表）、有效订单额、`毛利润（估）`、`毛利率（估）`、卖家订单额、退款金额、头程、尾程&全程、运费回扣、头程手续费、采购成本、平台佣金、活动手续费、结算手续费、VAT金额、平均广告花费（估）、平均运营成本（估）；
- **首行是汇总行**（订单号形如 `有效订单量：1`）→ 分析前剔除；
- 已知限制：`订单产品列表` 只有商品 ID，**没有单品金额拆分**；只能按订单/产品组合分析，**禁止虚构单品利润**。

## 七、分析流程（10 步）

1. 读汇总表 → 清洗 → 剔除合计行 → 填充分组列；
2. 计算毛利率：有 `毛利率` 列直接用；否则 `毛利率 = 毛利润 ÷ 销售额`；无法计算标"不可计算"；
3. 筛选：`毛利率 ≥ 15%` → 重点分析集；`< 15%` → 预警集；重点集为空 → 输出"整体未达标"+总体建议；
4. 按【站点名称】关联订单明细（`details[].itemName` 精确匹配；匹配不上列入"未关联明细"）；
5. 读明细 → 剔除汇总首行 → 清洗；
6. 按产品/订单聚合：销售额、毛利润、毛利率、订单量、退款率、广告费占比；
7. 标记：高贡献产品 / 低毛利产品 / 亏损产品 / 高退款产品；
8. 参数诊断（7 项，有数据才分析，无数据标"缺列"）：
   产品结构、定价与折扣、广告、退款、成本（采购/物流/佣金/VAT）、店铺健康（评分/罚分/预售/上架库存）、订单结构（订单量/客单价/买家数）；
   每项输出：**现状值 → 与毛利率/利润的关系 → 是否问题 → 影响程度（高/中/低）**；
9. 生成建议：每重点店 3~5 条，带数据依据与预期影响；按"影响大、可执行、成本低"排序；另给 3 条跨店铺结论；
10. 出报告 + 校验数字可追溯。

## 八、指标公式与边界

| 指标 | 公式/规则 | 边界 |
|---|---|---|
| 店铺毛利率 | 毛利率列，或 毛利润 ÷ 销售额 | 销售额=0 → 不可计算 |
| 产品毛利率 | 产品毛利润 ÷ 产品销售额 | 销售额=0 → 不可计算 |
| 产品销售额占比 | 产品销售额 ÷ 店铺销售额 | 结构分析 |
| 退款率 | 退款金额 ÷ 销售额（或退款单数 ÷ 订单数，按实际字段） | 字段缺失 → 跳过 |
| 广告费占比 | 广告费 ÷ 销售额 | 字段缺失 → 跳过 |

- 金额 2 位小数；比例输出百分比 1 位小数；
- 缺失值（空、`-`、`~`）按缺失处理，不参与计算，报告列出；
- 每个结论数字必须能追溯到具体文件/列/行，**禁止编造**。

## 九、校验规则

- 汇总表缺 4 个指标列或店铺维度列 → 停止分析并说明缺列；
- 关联校验：`details[].itemName` 与【站点名称】精确匹配，匹配不上单列"未关联明细"；
- 数量校验：明细份数 = 汇总表店铺行数 − missingItems；
- 勾稽校验：`Σ产品销售额 ≈ 店铺销售额`（允许 5% 业务误差，超出标注）；
- 主键唯一：店铺按站点名称唯一；产品按产品ID/Listing 唯一。

## 十、报告结构（8 节，内容必须齐全）

1. **结论摘要**：3~5 条核心结论（达标店数、整体毛利率、主要问题、建议优先级）；
2. **数据口径**：来源与 jobId、汇总表/明细份数、筛选条件、阈值（默认 ≥15%）、缺失/异常说明；
3. **达标店铺**（毛利率 ≥ 15%）：店铺 / 站点名称 / 销售额 / 毛利润 / 毛利率 / 净利润 / 主要问题；
4. **产品级分析**（逐店）：高贡献 / 低毛利 / 亏损 / 高退款产品，产品结构与毛利贡献；
5. **参数诊断**：7 项按"现状 → 关系 → 问题 → 影响"输出；
6. **优化建议**：每店 3~5 条 + 3 条跨店铺结论，带数据依据与预期影响；
7. **预警**（毛利率 < 15%）：店铺 / 毛利率 / 毛利润 / 建议动作；
8. **附件**：汇总表路径、明细路径、jobId、限制与未决。

格式：**单文件 HTML（工厂标准，内联 CSS）**；如业务要求 Markdown，可另附 `.md`，内容同上。
生成报告时必须显式传本次任务的数据文件，禁止默认"最新 job"。

## 十一、异常与重试

| 场景 | 处理 |
|---|---|
| `waiting_verify`（扫码） | 返回 verifyUrl 让用户扫码，暂停；不自动重试 |
| 轮询超时 | 再查一次状态；仍无终态 → 输出超时说明 |
| 任务 failed | 原样输出 error；同参数最多重试 1 次 |
| 单店明细失败 | 记 missingItems，继续 |
| 字段缺列 | 标"缺列"跳过对应分析，不影响其它结论 |
| 销售额=0 / 空数据 | 标"无数据/不可计算"，不生成建议，不覆盖旧报告 |
| 页面结构变化 | 抛错 + 截图 + 可读原因；更新选择器后重跑 |

## 十二、验收清单

### MVP（首版必须过）
- [ ] 真机连续 **3 次**任务 `done`；
- [ ] 汇总表行数 = 页面店铺行数；明细份数 + missingItems = 店铺行数；
- [ ] `details[].itemName` 与【站点名称】逐行对应；
- [ ] 汇总表/明细可解析，关键字段断言通过；
- [ ] 失败场景各 1 例：非法参数 → failed；单店失败 → missing 且任务仍 done；
- [ ] `onlySummary=true` → 只出汇总表、`details=[]`；
- [ ] 报告 8 节齐全，数字与源文件可对照；
- [ ] 非默认参数（换线路/站长）再跑一次成功。

### 完整档（上线前）
- [ ] 长稳 10 次无内存/句柄/磁盘异常；
- [ ] 3 任务排队串行完成；服务重启后已完成任务 `/result` 可读；
- [ ] 登录过期 → waiting_verify → 扫码继续；
- [ ] 空数据、边界日期、乱码参数；
- [ ] 证据包：jobId、产物、截图、校验输出、启动日志。

## 十三、技术实现约束（工厂 v3）

1. **参考实现**：`plugins/concise-analysis/service/crawler.js`（legacy，仅作页面链路参考，**不要照抄其 server/job 架构**）。
2. **新插件按 v3**：
   - `platform/manifests/<id>.json` 单一事实源（端口/taskType/serverName/路径/凭证键/是否写操作）；
   - `plugins/<id>/service/server.js` 只做 boot：`boot(manifest, require('./crawler').runJob)`；
   - MCP 薄壳放 `deployment/tools/<id>-mcp`，`node_modules` 用 Junction；
   - 报告用 `factory-kit/report-kit.mjs`；技能写 `deployment/skills/<id>/SKILL.md`（10 章 + 字段校准 + 例外表 + 待确认）。
3. **页面适配**：所有选择器集中在一处（`SEL` + 候选数组）；跨 frame 搜索；禁止固定 sleep；
   下载当场 `ctx.saveFile` 绑定 itemName；主报表失败抛错、单店失败隔离。
4. **端口**：从 `deployment/registry.md` 取下一个空闲端口，不复用 8790（legacy 在用）。
5. **凭证**：DPAPI（`factory secret`）；报告/日志不出现明文；报告账号脱敏。
6. **验收命令**：`factory render` → `factory doctor --health` → `factory test` → `factory smoke <id>`，全绿才算完成。
7. **已知待补**：周期参数（date/dateRange）、币种/时区口径、单品级拆分（需数据源支持）。

## 十四、红线与停手条件

1. **只读分析**：不修改任何业务系统；不做写操作（如"推送建议到外部系统"需另走写操作规范 + 审批）。
2. 不绕过验证码/风控；不共享账号；不编造数据/选择器成功。
3. 明细缺失不得用汇总表伪造产品级分析。
4. 遇到：无权限/凭证失效/报表菜单或表头结构变化且无法在 1 次内修复 → **停止**，给业务人员一条明确行动项。
5. 未验证不得说"完成"；每个结论贴命令或文件证据。
