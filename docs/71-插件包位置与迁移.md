# 71 · 插件包位置与换机器迁移

> 目标：插件开发完成后，能明确知道包在哪、安装后在哪、换机器要复制什么、不能复制什么。

## 1. 位置总览

| 类型 | 位置 | 是否要迁移 |
|---|---|---|
| 插件源包 | `data/generator/runs/<requestId>/dist/<id>-<version>.zip` | **要，核心交付物** |
| 生成目录 | `data/generator/runs/<requestId>/<id>/` | 可选，排查用 |
| 安装缓存 | `%LOCALAPPDATA%\dsh-factory\bundles\<id>-<version>\dsh-plugin-<id>\` | **不要**，目标机重装生成 |
| DSH profile | `%USERPROFILE%\.dsh\profiles\<profile>\` | **不要整体复制**，重装再生成 |
| 插件历史 | `data/registry/plugins.json` | 可选，含本机绝对路径 |
| 本地目录 | `catalog/plugins.json` | 可选，需重新生成 |
| 插件运行数据 | `DSH_PLUGIN_DATA_DIR` 或插件结果给出的目录 | 按业务需要复制 |
| 工厂密钥 | `platform/secrets/service-tokens.json` | **绝对不要复制/提交** |

## 2. 最终交付物只有一个

正式插件交付时，核心就是：

```text
<id>-<version>.zip
```

例如：

```text
data/generator/runs/req_20261117072140_e0cee5/dist/boss-resume-0.5.0.zip
```

这个 zip 已经包含：

```text
index.js
cordis.patch.yml
package.json
lib/
skills/
tests/
build.json
node_modules/     # 已验证打包时包含依赖
fixtures/
docs/
```

所以换机器时，**复制 zip 就够了**，不需要复制整个 `runs/` 目录，也不需要复制 AppData 下的安装缓存。

> **工厂项目只提交源码，不提交插件产品。**
> `data/generator/` 是运行产物目录，默认被 `.gitignore` 忽略；生成后应复制到发布位置，项目仓库中不保留插件包。
> 需要把运行数据放到项目外时，设置 `FACTORY_DATA_ROOT` 指向外部目录即可。

## 3. 安装后在哪里

执行安装后：

```powershell
node scripts/dsh-factory.cjs install "D:\packages\boss-resume-0.5.0.zip" --profile desktop
```

会生成：

```text
%LOCALAPPDATA%\dsh-factory\bundles\<id>-<version>\dsh-plugin-<id>\
```

并注册到：

```text
%USERPROFILE%\.dsh\profiles\<profile>\
```

DSH 实际加载的是 profile 里的插件，不是 zip 文件本身。

## 4. 查询插件包位置

```powershell
node scripts/plugin-package-info.cjs --id boss-resume
```

输出：

- 最新版本
- zip 路径 / 是否存在 / SHA-256
- 生成目录
- 本机安装缓存
- profile 路径

## 5. 换机器迁移：只迁插件

在旧机器：

1. 找到最新 zip
2. 记录 SHA-256
3. 把 zip 和校验值复制到 U 盘/网盘
4. 如果插件有业务数据，单独复制运行数据目录
5. 不要把 `platform/secrets`、token、cookie、浏览器 profile 一起打包

在新机器：

1. 安装 Node 24
2. 安装 DSH
3. 安装插件工厂（或至少保留 `scripts/dsh-factory.cjs`）
4. 复制 zip
5. 安装：

```powershell
node scripts/dsh-factory.cjs install "D:\packages\boss-resume-0.5.0.zip" --profile desktop
```

## 5.1 升级与回滚

升级同 id 的新版本时，安装器会先移除旧 link，再安装新版本，避免 profile 仍指向旧目录：

```powershell
node scripts/dsh-factory.cjs install "D:\packages\boss-resume-0.6.0.zip" --profile desktop
```

回滚到上一个已安装版本：

```powershell
node scripts/dsh-factory.cjs rollback boss-resume --profile desktop
```

先预览将回滚到哪个版本：

```powershell
node scripts/dsh-factory.cjs rollback boss-resume --dry-run
```

指定历史版本：

```powershell
node scripts/dsh-factory.cjs rollback boss-resume --version 0.5.0 --profile desktop
```

回滚只改 profile 链接，不删除历史 zip；重启 DSH 后生效。

6. 重启 DSH
7. 验证插件工具/技能出现
8. 重新配置凭证、登录态、应用路径

## 6. 换机器迁移：迁移整个工厂

如果要迁移整个工厂，而不是单个插件：

```text
复制：
  apps/
  packages/
  platform/
  scripts/
  docs/
  benchmarks/
  package.json
  package-lock.json (如存在)
  install.cmd / install.sh
  start-factory.cmd / start-factory.sh

不要复制：
  node_modules/
  data/generator/runs/ 中的临时文件（除非要保留历史插件）
  data/installer/
  platform/secrets/service-tokens.json
  DSH profile
  AppData 下的安装缓存
```

新机器：

```powershell
install.cmd
start-factory.cmd
```

然后按需重新生成/安装插件。

## 7. 插件数据与凭证

### 运行数据

例如采集任务、报告、日志，通常在：

```text
DSH_PLUGIN_DATA_DIR
```

或插件结果里给出的 `output_dir`。

迁移时：

- 只复制业务结果（Excel/报告/任务状态）
- 不复制浏览器 profile、cookie、token
- 确认目标机有写权限

### 凭证

插件 zip **不包含**：

- API Key
- 登录 cookie
- 微信/BOSS 登录态
- 浏览器用户目录

新机器必须重新配置：

- 环境变量
- DSH credentials
- 扫码登录
- 应用安装路径

## 8. 校验包是否完整

```powershell
Get-FileHash "D:\packages\boss-resume-0.5.0.zip" -Algorithm SHA256
```

对比交付时记录的 SHA-256。

或使用目录安装：

```powershell
npm run catalog:install -- --id boss-resume --catalog catalog/plugins.json
```

## 9. 迁移检查清单

```text
[ ] 已拿到 zip，而不是只拿到 runs 目录
[ ] 已记录 zip 的 SHA-256
[ ] 新机器已安装 Node 24
[ ] 新机器已安装 DSH
[ ] 已选择正确 profile
[ ] 已安装 zip
[ ] 已重启 DSH
[ ] 工具/技能已出现
[ ] 凭证/登录态已重新配置
[ ] 插件运行数据已按需复制
[ ] 没有复制 token/password/cookie/browser profile
[ ] 已跑一次最小真实输入验证
```

## 10. 不要做的事

- 不要把 `%LOCALAPPDATA%\dsh-factory\bundles` 直接拷到另一台机器
- 不要整体复制 `~/.dsh/profiles` 来迁移插件
- 不要复制 `platform/secrets/service-tokens.json`
- 不要把 `catalog/plugins.json` 里的本机绝对路径当成可迁移路径
- 不要只复制 `runs/` 下的源码目录而不带 zip
- 不要假设 `node_modules` 能跨操作系统使用（原生依赖需重装）
