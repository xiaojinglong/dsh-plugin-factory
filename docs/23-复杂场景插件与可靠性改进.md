## 二、压测暴露并修复的平台缺陷（6 项）

| # | 缺陷（修复前证据） | 影响 | 修复 |
|---|---|---|---|
| D1 | `bootstrap` 只从 `process.env.SERVICE_TOKEN` 取鉴权 token，manifest 的 `runtime.serviceToken` 未注入 → 所有 v3 服务实际**未鉴权**：无 token `GET /jobs` 返回 200 | 任何本机进程可读任务与提交任务 | `platform/factory/bootstrap.js`：env 优先，回退 manifest `serviceToken`；`doctor --health` 增加"无 token 必须 401 / 带 token 必须 200"实检 |
| D2 | 写插件 `dry_run` 同 `idempotency_key` 二次提交触发 SQLite 唯一索引冲突 → **HTTP 500** | 预演重跑直接报错 | `platform/runtime/index.js`：幂等键只在"真实写"时落库；`GET /jobs` 未鉴权改为 401 |
| D3 | 写额度统计包含 `dry_run` 任务 → 3 次预演即占满 3 次额度，真实写被 429 | 预演挤占真实额度 | `platform/runtime/store.js`：新增 `dry_run` 列（旧库自动 `ALTER TABLE` 迁移），`writeCountToday` 只统计真实写 |
| D4 | 额度检查在幂等检查之前 → 额度用尽后同一 `idempotency_key` 重试返回 429 而不是复用原任务 | 幂等重试语义被破坏 | `runtime/index.js`：**幂等优先于额度** |
| D5 | `factory render` 每次追加生成的插件注释行且不清理历史注释 → patch 注释重复累积 | patch 膨胀、难审计 | `platform/factory/cli.cjs`：`stripMcpBlocks` 清理历史生成注释；连续两次 render 结果稳定（11 条目 / 11 注释） |
| D6 | `doctor` 把"开启鉴权但无 DPAPI 凭据"误报为 WARN（token 在 manifest，不需要 .enc）；且不校验 patch token 与报告生成器 | 误报 + 配置漂移无法发现 | `cli.cjs`：细化告警条件；新增 patch `MCP_SERVICE_TOKEN` 与 manifest 一致性检查、报告生成器存在性检查 |

### 2.1 修复前后对照（实测）

```
# 修复前（运行时实例）
GET /jobs 无 token              → 200 {"jobs":[...]}          ← 未鉴权
dry_run 同 idempotency_key 二次 → 500 UNIQUE constraint failed
3 次 dry_run 后真实写            → 429（3/3）
GET /jobs 未鉴权                 → 200 {"error":"unauthorized"}

# 修复后
GET /jobs 无 token              → 401
GET /jobs 带 manifest token      → 200
dry_run 同 key 二次              → 202 + 202
dry_run ×3 后真实写              → 202（预演不占额度）
额度用尽后重复既有 key           → 200 {deduplicated:true}（幂等优先）
```

> 修复后已重启 11 个 v3 服务（`concise-analysis` 为 legacy，未迁移 runtime，保持原样）。
> 全部 v3 服务当前的鉴权实测：`no-token=401 / token=200`。

## 六、已知限制与后续

1. **模拟边界**：三个插件的数据源为内置模拟实现（bulk-sync 模拟上游 / coupon-push 本地模拟外部系统 / page-audit 本地站点），
   不代表真实业务；接真实系统时只替换执行层的"取数/写入"实现，四道闸与 runtime 契约保持不变。
2. **重试可观测性**：`runner-api` 的自动重试次数未写入 dataset，报告只能说明"首轮失败后重试成功"（日志可查）。
   建议后续在 dataset.extra 增加 `retryCount`。
3. **任务级看门狗**：runtime 目前依赖 runner 主动检查 `ctx.isAborted()`；若 runner 卡死在单次 await（如网络无超时），
   单 worker 会被阻塞。建议后续增加可选 `jobTimeoutMs`（默认关闭，浏览器/长任务按插件配置）。
4. **文件系统型类型**：`fs-ledger` 使用 `type: "file"`（工厂首次出现），`doctor`/契约测试目前不限制 type 枚举；
   若后续扩展更多类型，建议在 `docs/10` 与契约测试中补齐枚举校验。
5. **legacy**：`concise-analysis` 仍未迁移共享 runtime（无鉴权、无 jobs 接口），本次未改动；迁移仍是 HANDOFF 的待办。
