# 27 — M6 硬化与试点（A 单机版）

> 状态：M6 ~75%（限流、health、恢复、保留、巡检+webhook、演练、计划任务已实现；真实试点未开始）。

## 1. 已实现

- **POST 限流**：控制面按 IP 固定窗口（默认 120 次/分钟，`CONTROL_PLANE_RATE_LIMIT` 或 `createControlPlane({rateLimit})`），超限 429 + `Retry-After`。
- **health 就绪**：`GET /health` 返回 `checks.db`，DB 异常时 503；GET 不受限流影响。
- **错误处理**：统一 4xx/5xx 错误结构；5xx 记日志。
- **备份/恢复**：`POST /admin/backup`；`apps/control-plane/restore.cjs` 可恢复到新数据根并保留旧库；单测覆盖恢复读取与非法备份拒绝。
- **审计保留**：`POST /admin/prune`（默认 dry-run）删除旧 audit 并记录 `audit.prune`；参数 0–3650 天。
- **巡检**：`scripts/health-check.cjs` 检查 health/metrics 与阈值（audit/dbSize/failed），退出码可接计划任务；`/metrics` 增加 dbSizeBytes；失败可用 `--webhook`/`FACTORY_ALERT_WEBHOOK` 通知。
- **容量**：`POST /admin/prune-requests` 清理终态旧请求（failed/installed），级联 steps/audit/idempotency；默认 dry-run。
- **试点演练**：`scripts/pilot-drill.cjs`：需求单→staging→accept→备份→恢复→巡检，临时数据根、输出 `pilot-drill.json`；单测覆盖。
- **计划任务**：`ops-schedule` 生成 health/backup/drill 任务（Windows schtasks + crontab），`ops-backup` CLI；见 `docs/29-运维计划任务.md`。
- **审计**：需求单/步骤/runner/accept 均有审计记录。
