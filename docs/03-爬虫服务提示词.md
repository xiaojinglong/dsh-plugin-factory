## 二、硬性要求（从本次实测沉淀，必须写进需求）

1. **周期参数化**：若业务需要长周期/同比，执行层必须支持 `date`/`dateRange` 参数（本次经营分析缺此能力，长周期做不了）。
2. **端口一致性**：`mcp-config.json.baseUrl` 端口 = `.env.PORT`；交付时自动校验并在交付说明中打印。
3. **服务常驻**：交付"启动方式"（pm2 / 计划任务 / 启动脚本）+ `/health` 自检 + 日志落盘路径；不能只写 `npm start`。
4. **失败语义**：单店/单明细失败 → `addMissing` 后继续；主报表失败 → `failed` 带业务前缀错误。
5. **产物登记**：下载当场 `ctx.saveFile({itemName,fileName,kind})`，禁止事后按文件名猜映射。
6. **等待策略**：禁止固定 sleep；全部元素断言/networkidle/waitForEvent。
7. **参数化铁律**：默认值只在 `DEFAULT_FILTERS` 一处定义；设置与断言同源；验收必须用**非默认值**跑一次。
8. **功能开关**：`onlySummary:true` / `includeDetails:false` 语义写清（`details=[]`、`missingItems=[]`）。
9. **失败留证**：失败截图、关键 DOM、可读 progress。
10. **不改 FROZEN**：`server.js`/`job.js`/`util.js` 不可改；改前后给哈希对比。

## 三、验收分两档（按场景选，别一上来就全套）

### MVP 档（新插件首版必过，约 1–2 小时）
- [ ] 离线 e2e（mock）通过
- [ ] 真机连续 **3 次** `done`
- [ ] 汇总表列/行数正确；明细份数 = 店铺行数；`itemName` 逐行对应
- [ ] 文件可解析（xlsx/json/csv），关键字段值断言通过
- [ ] 失败场景各 1 例：非法参数 → failed；单店失败 → missing 且任务仍 done
- [ ] `mcp-config.json` 可 `JSON.parse`，端口与 `.env.PORT` 一致

### 完整档（上线前/对外交付）
- [ ] 长稳 10 次无内存/句柄/磁盘异常
- [ ] 3 任务排队串行完成；服务重启后已完成任务 `/result` 可读
- [ ] 登录过期 → waiting_verify → 扫码继续
- [ ] 非法/乱码参数、空数据、边界日期
- [ ] 证据包：jobId、产物、截图、校验输出、启动日志（版本行）
