# 插件工厂（Plugin Factory）— 通用创造流程 v3.0

> 用途：用**一套通用流程 + 模板提示词**，快速创造 DSH 插件（Skill + Tool）。
> 一句话：业务人员写业务，AI 按提示词流水线干活，人工只做 3 个动作。
> 适用：爬虫型（页面自动化）与 API 型（接口取数）两种形态，共用同一套契约与提示词。

---

## 一、这套东西怎么用（30 秒）

**默认入口（v2，业务人员用这个）**：
1. 按 `21-业务描述模板.md` 写清业务（8 行，写 3 行也能开工）。
2. 把 `20-一键造插件提示词.md` 整段 + 业务描述发给 AI。
3. AI 自己读规范、套 `22-插件生成代码骨架.md`、勘探接口、开发服务/MCP/技能、部署、冒烟、自检、给报告。
4. 你只做 3 件事：**扫码**（首次/登录失效）、**重启 DSH**、**按验收清单抽查**。

**进阶入口（多插件编排/复杂场景）**：`00-总控提示词.md`（13 步 + 4 门禁），配合 `01`–`08` 子提示词。

## 三、13 步流程与 4 个门禁

```
S0 需求卡 ──🚦G1 口径确认
 ├─ S1 命名/端口/登记
 ├─ S2 初始化骨架            （01）
 ├─ S3 业务流程初稿          （02 阶段 A/B/C）
 ├─ S4 爬虫开发 + 真机验收  🚦G2  （03）
 ├─ S5 实测回填 SKILL.md     （04）
 ├─ S6 MCP 装配 + 自检      （05）
 ├─ S7 改 DSH 配置          （05 + templates/patch-*）
 ├─ S8 服务常驻
 ├─ S9 冒烟五连             🚦G3  （05）
 ├─ S10 重启 DSH

 ├─ S12 业务验收三段        🚦G4  （06）
```

**人工动作只有 3 个**：① 扫码（首次/失效）② 重启 DSH ③ 抽查验收签字。

## 四、两种形态：爬虫型 / API 型

| 维度 | 爬虫型 | API 型 |
|---|---|---|
| 执行层 | Playwright 页面自动化（`crawler.js`） | HTTP 接口取数（`fetcher.js`） |
| 契约层（5 工具） | 相同 | 相同 |
| Skill 层（提示词） | 相同 | 相同 |
| 状态机 | queued→running→(waiting_verify)→done/failed | queued→running→done/failed |
| 复用方式 | 见 `03-爬虫服务提示词.md` | 见 `08-API型插件适配.md` |

> 记住：变的只有执行层，**契约层与提示词层一行不改**，这就是能复用的根因。

## 七、三条纪律（违反会返工）

1. **顺序不能反**：先流程初稿 → 跑爬虫 → 再回填 SKILL.md（字段校准只能来自实测）。
2. **命名/端口/服务地址三处必须一致**：`config.json` ↔ `.env.PORT` ↔ `patch.env`，且登记进 registry。
3. **未冒烟不重启，未验收不交付**：冒烟在重启 DSH 之前做；业务验收在声称完成之前做。

接口探通后，单插件 ≈ 7–10 分钟；人工介入 0 次；返工 2 次（产物形状、import 路径）——两项已固化进 `10` 与 `09`。

### 8.2 批量生产规则（同源多插件）

1. **一个数据源 = 一套执行层模板**：`api-runner.js` 写一次，每个业务 `fetcher.js` 只写 10 行配置（task/path/pageSize/buildBody）。
2. **一个业务 = 一个 MCP + 一个 Skill + 一个端口**：MCP 代码完全相同，只改 `serverName` 与 `config.baseUrl`。
3. **产物统一契约**：见 `10-标准产物契约.md`（dataset.json）；报告统一用 `factory-kit/report-kit.mjs`。
4. **接口勘探前置**：见 `09-API接入勘探清单.md`，未探完不写 fetcher。
5. **环境预检前置**：见 `11-环境预检.ps1`，避免 EPERM/端口/依赖类阻塞。
6. **热加载**：改 `cordis.patch.yml` 后技能与 MCP 工具可直接生效（实测），仅在换 MCP 可执行文件路径时建议重启。

   **怎么确认生效（盲测补充）**：看会话里是否出现 `mcp__<serverName>__*` 五个工具与技能 `<id>`；没有就重启 DSH 再看。命令行侧可用 `12-工厂自检.ps1` 验证 patch↔config↔端口一致。
7. **开发副本 vs 运行副本（盲测补充）**：`<plugin>/mcp` 是开发副本，`D:\www\dshskills\tools\<id>-mcp` 是运行副本（patch 指向它）。同步方式：复制 `index.js/config.json/package.json/smoke.cjs`，`node_modules` 用 Junction 指向任意一个已装好的 MCP，避免重复安装。

### 8.3 度量口径

| 指标 | 目标 |
|---|---|
| 单插件耗时（接口已探通） | ≤ 20 分钟 |
| 人工介入次数 | ≤ 3（扫码/授权/审批） |
| 返工次数 | ≤ 1 |
| 冒烟通过率 | 100%（MCP 五连） |

### 9.2 已知使用边界

- 空数据：服务 `done`、报告生成器 `exit 2` 且不覆盖旧报告（契约 §5）。
- 接口业务错误：原样透传为 `failed` 原因（如 `code=100400`）。
- 参数超限：`pages` 由 `maxPages` 截断；`pageSize` 受接口上限约束。
- 脚本编码：`.ps1` 必须 UTF-8 **带 BOM**（PS 5.1 要求），新增脚本请照做。

## 十、v3 平台化（2026-11-14，共享 runtime）

工厂从"每个插件一套代码"升级为"**一份 runtime + manifest + 一条 CLI**"。详见 `D:\www\dshspirder\platform\README.md`。

### 10.1 新插件必须做的 5 件事

1. 写 `platform/manifests/<id>.json`（端口/taskType/serverName/路径/凭证键/是否写操作）；
2. `service/server.js` 只做 9 行：`boot(manifest, require('./<runner>').runJob)`；
3. runner 用共享 `runner-api.js`（API 型）或 Playwright（浏览器型）；
4. 凭证用 `factory secret <id> set KEY=VALUE` 加密（**不写明文 .env**）；
5. 跑 `factory render` → `factory doctor --health` → `factory test` → `factory smoke <id>` 全绿。

### 10.2 治理能力（v3 新增）

| 能力 | 说明 |
|---|---|
| 持久化任务引擎 | SQLite 存储、重启恢复（running→failed）、取消 API、按天保留清理 |
| 鉴权 | 每插件独立 token；MCP 通过 `MCP_SERVICE_TOKEN` 携带；无 token 401 |
| 写操作治理 | `confirm_write=true` + dry_run 预演 + 每日配额 + 幂等键 + 审计日志 |
| 凭证 | DPAPI 加密（`platform/secrets/<id>.enc`），.env 不再有明文密钥 |
| 指标/日志 | `GET /metrics`（p50/p95/失败分类/队列）+ JSON 日志 5MB 轮转 |
| 单一事实源 | manifest → 自动生成 `cordis.patch.yml` 与 `dshskills/registry.md` |
| 测试门禁 | `factory test`：12 用例（契约 + runtime 集成） |
| 守护 | `factory watch`：服务掉线自动拉起 |
