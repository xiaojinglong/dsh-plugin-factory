## 2. 新用户：一条命令安装

前置：已安装 **Node.js >= 24** 和 **DSH**。

```powershell
git clone https://github.com/xiaojinglong/dsh-plugin-factory.git
cd dsh-plugin-factory
install.cmd
```

或者：

```powershell
node install.cjs
```

`install.cmd` 会自动：

1. `npm ci` 安装依赖
2. 安装 Playwright Chromium（浏览器类插件需要；失败只警告）
3. 检查并安装 DSH 集成（自动备份）
4. 启动控制面 + 28 个插件服务
5. `doctor --health` 自检
6. 安装登录自启（用户 Startup 目录，隐藏窗口）

看到 `[install] 完成` 后，**重开一次 DSH**，直接对 AI 说你要做什么。

日常：

- 启动：双击 **`start-factory.cmd`**
- 停止：双击 **`stop-factory.cmd`**

## 3. 手动安装（install.cmd 失败时排障）

```powershell
cd D:\www\dsh-plugin-factory

# 1) 检查 DSH 环境
node apps/installer/installer.cjs check

# 2) 安装/修复 DSH 集成（会备份）
node apps/installer/installer.cjs install
# 如果 restart 后看不到 factory-control，执行：
node apps/installer/installer.cjs repair

# 3) 启动控制面（保持这个窗口）
node apps/control-plane/server.cjs

# 4) 启动全部插件服务
node platform/factory/cli.cjs up

# 5) 健康检查
node platform/factory/cli.cjs doctor --health
```

然后**重开一次 DSH**，会话里应出现：

- `factory-control`：create_request / write_runner / accept_request / list_plugins 等 9 个工具
- 28 个插件 MCP 工具 + 对应 skills（如 `git-flow-audit`、`xborder-restock`、`trend-selection-audit`）

## 4. 用已有插件

### 方式 A：在 DSH 里直接用

示例：

> 用 `git-flow-audit` 审计这个仓库的 Issue/分支/PR/CI 完整性

> 用 `xborder-restock` 跑一次多站点补货，报告给我

> 用 `trend-selection-audit` 合并 Google Trends 和选品工具 CSV，输出推荐

### 方式 B：直接调服务（调试/自动化）

- 控制面：`http://127.0.0.1:8780/health`
- 插件清单：`GET /plugins`（Bearer token）
- token：`data/control-plane/token`（不要提交）
- 任务：`POST /jobs`、`GET /jobs/:id`、`GET /jobs/:id/result`
- 报告：`plugins/<id>/report/<id>-report.html`
- 任务数据：`plugins/<id>/service/data/jobs/<jobId>/`

## 5. 用工厂造新插件

### 4.1 在 DSH 里

1. 让 agent 用 `create_request` 建需求单（brief + params：pluginId/name/type/fixture/runnerFile/reportFile）。
2. 用 `write_runner` 提交业务 runner（或让 agent 生成）。
3. 跑流水线：

```powershell
node apps/generator/pipeline.cjs --request <requestId>
```

4. 看 staging 报告：`data/generator/runs/<requestId>/<pluginId>/report/`
5. 业务确认后：

```text
accept_request(requestId, acceptedBy)
```

6. 安装：

```powershell
node apps/installer/plugin-install.cjs install --source <stagingPluginDir> --root D:\www\dsh-plugin-factory
```

7. 重开 DSH 或 `installer repair` 后使用新插件。

### 4.2 已有场景包

- 9 岗位场景：`scenarios/<id>/fixture.json` + `runner.js`
- Wave 1：`git-flow-audit`、`boss-candidate-score`、`product-selection-score`、`ops-daily-audit`、`supplier-quote-compare`
- 趋势选品：`scenarios/trend-selection-audit/`
- 1M 日志：`scenarios/log-anomaly-audit/`
- CSV/API 适配器：`scenarios/csv-adapter.mjs`、`scenarios/api-adapter.mjs`

## 6. 日常运维

```powershell
# 状态
node platform/factory/cli.cjs status
node platform/factory/cli.cjs doctor --health

# 单插件启停
node platform/factory/cli.cjs up <id>
node platform/factory/cli.cjs down <id>

# 全量服务
node platform/factory/cli.cjs up
node platform/factory/cli.cjs down

# 测试
node platform/factory/cli.cjs test      # 105/105

# 备份控制面（start-factory 每次启动也会自动备份一次）
node scripts/ops-backup.cjs
```

### 回滚

```powershell
# 卸载插件
node apps/installer/plugin-install.cjs uninstall --id <id> --root D:\www\dsh-plugin-factory

# 恢复 DSH 集成（还原 patch）
node apps/installer/installer.cjs uninstall
# 或从备份回滚
node apps/installer/installer.cjs rollback
```

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 重开 DSH 后工具消失 | `node apps/installer/installer.cjs repair`，再重开 DSH |
| 服务全 DOWN | `node platform/factory/cli.cjs up`（没有自启，DSH 重启会杀子进程） |
| 端口冲突 | `doctor --health` 看端口；`factory down <id>` 后重启 |
| 报告没生成 | 看 `plugins/<id>/service/data/jobs/<jobId>/` 与 job 状态/error |
| 401/403 | 检查 manifest 的 serviceToken 与请求头 |
| 安装失败 EPERM | 先停对应服务，避免 Windows 目录占用；安装器已改为失败不删原目录 |
| 凭证丢失 | haina 等账号只在进程环境；重启需重新注入，未落盘 |

## 8. 上线前建议补的（按优先级）

1. **自动启动**：计划任务/服务包装，避免每次手动 `up`。
2. **凭证管理**：DPAPI/secrets，不把账号放 `.env`/命令行。
3. **备份计划**：控制面 DB + 插件数据每日备份。
4. **监控告警**：/health、任务失败率、端口、磁盘。
5. **代码签名/分发**：正式对外前做。
6. **真实账号试点**：BOSS/卖家中心/1688 先只读，再草稿，再写。
