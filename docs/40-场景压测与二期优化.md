## 2. 大数据量压测

同一 runner，1k / 5k / 50k / 100k 行：

| 场景 | 1k 行 | 5k 行 | 50k 行 | 100k 行 |
|---|---|---|---|---|
| HR | 21ms | 53ms | 441ms | 937ms |
| 跨境补货 | 30ms | 40ms | 328ms | 759ms |
| 行政资产 | 17ms | 59ms | 551ms | 1122ms |
| 客服工单 | 17ms | 61ms | 520ms | 1144ms |
| 代码审计 | 14ms | 37ms | 314ms | 730ms |
| 内容检查 | 17ms | 56ms | 479ms | 1121ms |
| 关键词 | 11ms | 34ms | 291ms | 628ms |
| 渠道 ROI | 12ms | 34ms | 265ms | 565ms |
| 账号审计 | 12ms | 39ms | 355ms | 700ms |

- 全部成功；100k 行最慢 1144ms；堆峰值约 205MB。
- 50k 行报告：**248ms / 89KB**（明细最多展示前 500 行，KPI/规则仍按全量计算），可正常生成。
- 100k 仍可跑；1M 级需要流式/分页，否则内存线性增长。

## 2.1 CSV 真实数据接入

- `scenarios/csv-adapter.mjs`：CSV → 场景 fixture JSON，支持引号内逗号、双引号、CRLF、BOM、数字/布尔/数组字段。
- 字段映射在 `scenarios/<id>/csv-map.json`；样例 `scenarios/samples/xborder.csv`、`assistant.csv`。
- 已用 `scenarios/csv-pipeline-check.mjs` 把 CSV 转出的 fixture 走工厂 pipeline，**staging 通过**（`xborder-csv-smoke`）。
- CSV→跨境 5 行：引号字段、数字转换正确；CSV→账号 5 行：布尔字段正确。

## 2.2 API 分页接入

- `scenarios/api-adapter.mjs`：分页 API → 场景 fixture JSON。
- 支持 `page/per_page` 参数、`itemsPath`（如 `data.list`）、Bearer token（从环境变量读取，不进命令行）、429/5xx 自动重试、最多页数。
- 本地 mock 测试覆盖：第一页 500 自动重试、两页合并、token 透传、字段归一化。
- 真实 API 只需改 `--url/--path` 与字段映射，不需要把 key 写进仓库。

## 2.3 报告上限优化

原报告 5k 行整表输出 **882KB**；加入 `MAX_DISPLAY=500` 后降到 **89KB（约 1/10）**，避免大报告拖慢浏览器/邮件。完整数据仍在任务 dataset 中，可按需导出。
