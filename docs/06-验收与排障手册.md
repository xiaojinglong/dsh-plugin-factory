## 二、业务验收三段（G4）

### 第 1 段：数据对账（Agent 做，主管看结论）

| 校验 | 做法 | 通过标准 |
|---|---|---|
| 明细 ↔ 汇总 | Σ明细关键字段 = 汇总对应列 | 误差 ≤ 业务约定（默认 0） |
| 总量一致 | 明细订单量合计 = 汇总订单量 | 相等 |
| 主键唯一 | 店铺/产品按主键去重 | 无重复 |
| 筛选生效 | 结果列值 = 筛选值 | 逐列断言 |
| 口径异常 | 「字段为 0/空」逐项列出 | 全部标注，不静默 |

### 第 2 段：主管抽查（人工，10 分钟）

- 抽 1–2 家/1–2 个指标，与**页面原始数据**对照；
- 抽查项：汇总表某列数值、某店明细行数、某产品毛利；
- 结论：一致 → 签字；不一致 → 先查口径（列名/汇总 vs 明细/是否含退损），再查代码。

### 第 3 段：异常用例（Agent 做）

| 用例 | 预期 |
|---|---|
| 非法参数 | failed + 业务化错误 |
| 失败重试 1 次 | 同参数再失败即停，不编造 |
| 未完成取结果 | 409 原样透传 |
| 不支持文件类型 | 明确报错 |
| 文件不存在/坏 JSON | 明确报错 |
| 缺列 | 停止分析并列出缺列 |
| 空数据 | 输出"无数据"，不生成建议 |

## 三、四层排障路由

| 现象 | 层 | 查什么 | 修法 |
|---|---|---|---|
| 会话里没有这个技能 | Skill | 目录是否 `skills/<id>/SKILL.md`（不嵌套）；`name` 是否 kebab 且=目录名；frontmatter 是否可解析 | 改名/改层级 → 重启 DSH |
| 没有 MCP 工具 | 接入 | patch 是否插入；YAML 缩进；`id/serverName` 否冲突；`args` 路径是否存在；cwd 是否对 | 修 patch → 重启 DSH |
| 工具调用报错 | 服务 | 服务是否常驻；`/health`；`config.baseUrl` 端口；`.env.PORT`；登录态 `data/sessions` | 启服务/改端口/扫码 |
| 卡在 waiting_verify | 服务 | 二维码链接是否可打开；扫码人是否在线 | 扫码 → 重新查状态（MCP 不会自动扫码） |
| 报告数字不对 | 业务 | 先口径（列名/汇总vs明细/是否含退损/合计行），再筛选是否生效，最后才怀疑代码 | 回填 SKILL.md 字段校准 |
| 明细缺失但任务 done | 服务 | `missingItems` 的 reason | 单店重试/查权限 |
| 长任务超时 | 接入 | `toolCallTimeoutMs`（默认给 900000） | 调大或分批 |

## 四、证据留存规范

每次验收保存：`jobId`、汇总表/明细文件、页面截图、`meta.json`、校验输出、启动日志（含版本行）、采集时间与账号。
命名：`evidence/<业务标识>/<日期>/`。
