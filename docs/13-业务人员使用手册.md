# 13 · 插件工厂使用手册（业务人员版）

> 版本 v1.1（2026-11-13，按两次盲测反馈修订）
> 一句话：**用现成插件就说一句话；要新插件就把业务讲清楚交给 AI。你只做 3 个动作——扫码、重启 DSH、验收。**

---

## 一、一分钟看懂

一个"插件" = **技能（怎么分析）+ 工具（怎么取数）+ 服务（在哪跑）**。

现成插件（5 个，直接用）：

| 插件 | 用途 | 触发词示例 |
|---|---|---|
| `concise-analysis` | 经营分析（毛利率/达标店/优化建议） | "按经营分析做一次" |
| `listing-list` | 商品盘点（库存/动销/质量/合规） | "按 listing-list 盘点商品" |
| `shop-list` | 店铺盘点（状态/站点/团队/供给） | "按 shop-list 盘点店铺" |
| `ads-list` | 广告盘点（花费/CTR/ROI/止损） | "按 ads-list 盘点广告" |
| `draft-cleanup` | 草稿清理（DRAFT 积压/归档候选） | "按 draft-cleanup 清草稿" |

## 二、先选路径

| 路径 | 场景 | 你要做什么 | 耗时 |
|---|---|---|---|
| **A 用现成** | 已有插件能回答的问题 | 说一句话 + 验收 | 1 分钟（不含取数） |
| **B 同源加业务** | 同一数据源，新报表/新口径 | 讲业务 + 回答追问 + 验收 | 20–40 分钟 |
| **C 新建** | 新系统/新接口 | 准备凭证与接口示例 + 讲业务 + 验收 | 半天–1 天 |

> 判断：**数据源相同 → B；不同 → C**；只是跑一次 → A。

## 三、路径 A：跑一次已有插件（5 步，最常用）

### 第 1 步：说清楚"要什么"

直接对 AI 说，例如：

> 按 listing-list 盘点陈雄德名下在售商品，取 2 页，出 HTML 报告。

> 按 ads-list 盘点店铺 1097451512 在 2026-11-01～11-13 的广告，出报告。

> 按 shop-list 盘点我的店铺，取 2 页。

**不用你说 taskType、参数名、接口地址**——AI 会从技能文档里取。你只要说清：**哪个插件 + 谁/哪个店 + 时间范围 + 几页**。

### 第 2 步：AI 取数，你确认

AI 会返回：**任务号（jobId）+ 数据条数/总量 + 数据文件路径**。
你确认一句"条数对"即可；不对就让它换参数重跑。

### 第 3 步：生成报告

两种方式，任选：

- **让 AI 生成**：说"生成报告"（AI 会调用报告脚本）。
- **自己跑命令**（PowerShell 5.1 用 `;`，不要用 `&&`）：

```powershell
cd D:\www\dshspirder\listing-list; node gen-report.mjs
cd D:\www\dshspirder\shop-list;   node gen-report-shop.mjs
cd D:\www\dshspirder\ads-list;    node gen-report-ads.mjs
cd D:\www\dshspirder\draft-cleanup; node gen-report-draft.mjs
```

> 脚本默认**自动读取该插件最新一次任务的数据**；也可以指定某次任务的数据文件：
> `node gen-report.mjs D:\www\dshspirder\listing-list\service\data\jobs\<jobId>\listing_dataset.json`
> 报告页眉会写「任务：<jobId> / 取数时间：…」，**先看这两个再判断是不是新数据**。

### 第 4 步：打开报告

报告路径：`D:\www\dshspirder\<插件>\report\<插件>-report.html`，双击用浏览器打开（单文件、可离线）。

### 第 5 步：验收（见第五节清单）

## 四、路径 B / C：造一个新插件（业务人员版 5 步）

### 第 1 步：写下业务（6 要素）

1. 解决什么问题、产出什么
2. 数据从哪来（系统/接口地址/页面；有接口给示例请求）
3. 业务步骤（取数→算→出结果）
4. 规则阈值（达标线、异常判定、公式）
5. 边界（只读 / 含写操作；写操作必须审批）
6. 怎么算做对（抽查什么、谁签字）

> **凭证不用写进需求**：告诉 AI"凭证已放在服务端 .env"或"稍后由技术同事配置"即可，红线要求凭证不落仓库。

### 第 2 步：发给 AI 这段启动语

```
请按插件工厂流程帮我做一个插件：
1) 先读：D:\www\dshspirder\plugin-factory\README.md
2) 再读：09-API接入勘探清单.md、10-标准产物契约.md
3) 参考实现：D:\www\dshspirder\shop-list\（service/mcp/skills/report）
4) 共享报告套件：D:\www\dshspirder\factory-kit\report-kit.mjs
5) 我的业务（6 要素）：<粘贴>
6) 要求：只读、2 页采样、单文件 HTML 报告；完成后给冒烟证据与验收清单
```

### 第 3 步：回答追问（≤8 个/轮）

不知道就说"按默认"，AI 会标「默认，待确认」。

### 第 4 步：按需配合

- 爬虫型：首次登录/失效时扫码；
- 配置改完：重启 DSH（完全退出再打开）。

### 第 5 步：验收（同第五节）

## 五、验收清单（照着打勾）

| # | 检查项 | 怎么查 | 通过标准 |
|---|---|---|---|
| 1 | 技能在 | 会话技能列表出现 `<业务标识>`；调用 `mcp__<id>__*` 成功 | 出现且能调 |
| 2 | 数据新 | 报告页眉「任务/取数时间」= 本次 job；条数 = 你们约定的页数×条数 | 与本轮任务一致 |
| 3 | 口径清 | 报告「数据口径」写明：接口、参数、过滤规则、**库存/金额公式**、缺失处理 | 每项都能说清 |
| 4 | 数字对 | 用 job 的数据文件独立复算 1–2 个关键数（AI 可代做） | 与报告一致 |
| 5 | 报告可读 | 打开无乱码、无空表、无外链、章节完整 | 8 节齐全 |
| 6 | 限制已写 | 「限制与未决」写明样本覆盖率/站点偏差/无排序等 | 有且具体 |
| 7 | 凭证安全 | 报告/日志无明文凭证 | 不出现 |

> 第 4 条对账话术（发给 AI 即可）：「用 job 的 dataset.json 独立算一遍 X/Y/Z，跟报告对一下，列出差异」。

## 七、常见问题（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| 报告是旧数据 | 脚本自动取"最新任务"，但你刚跑的是更早任务；或手工复制过 dataset.json | 看页眉「任务/取数时间」；用 `node gen-report.mjs <jobId 的数据文件>` 指定 |
| `&&` 报错 | PowerShell 5.1 不支持 `&&` | 换成 `;`，或分两行 |
| `pm2` 不是命令 | 本机未装 pm2 | 用 `cd <插件>\service; node server.js` 启动；要常驻用 `start-<id>.bat` + Windows 任务计划 |
| 换负责人没生效 | 接口忽略 `shop_user_id`，实际按 `shop_user_name` 过滤 | 改 `shop_user_name`（如"陈雄德"），并在报告里核对站点/负责人 |
| 服务没起 | 机器重启/进程退出 | `cd <插件>\service; node server.js`；或跑 `12-工厂自检.ps1` 看哪个端口不通 |
| 报告空白/无数据 | 该参数/周期接口返回 0 条 | 换参数/周期重跑；脚本会拒绝生成空报告并保留旧报告 |
| 技能/工具不出现 | 配置未生效 | 重启 DSH；再跑 `12-工厂自检.ps1` |
| 不知道数据在哪 | 产物在 `service\data\jobs\<jobId>\` | 问 AI 要 `main.path`，或看报告页眉的任务号 |

## 八、红线（必须遵守）

1. **写操作必须审批**：调价、上下架、删除、发消息等，未经批准不得执行；现有 5 个插件均为只读。
2. **凭证不落库**：只放服务端 `.env`；报告与日志不得出现明文。
3. **不编造**：无数据写"无数据"，缺字段写"缺列"，缺渠道写"未核实"。
4. **样本要说明**：几页就是几页，报告「限制与未决」必须写覆盖率，禁止说成全量。

## 十二、v3 平台命令（2026-11-14 起）

工厂已升级为"共享 runtime + manifest + CLI"，日常运维只用这几条：

```powershell
cd D:\www\dshspirder\platform\factory

node cli.cjs status               # 看 8 个服务是否在线
node cli.cjs doctor --health      # 一键自检（配置/端口/凭证/健康/报告）
node cli.cjs up / down            # 启停全部（后台，PID 落盘）
node cli.cjs watch 15             # 守护：掉线自动拉起
node cli.cjs smoke <插件id>       # 单插件 MCP 五连冒烟
node cli.cjs clean                # 清理过期任务目录
node cli.cjs secret <插件id> set LISTING_API_KEY=xxx   # 凭证加密保存（不写明文）
```

新增插件时（v3 要求）：先建 `platform/manifests/<id>.json` → 写 9 行 `server.js`（boot）→
`factory render` → `factory doctor --health` → `factory test` → `factory smoke <id>`，全绿才算完成。
详细说明见 `D:\www\dshspirder\platform\README.md`。
