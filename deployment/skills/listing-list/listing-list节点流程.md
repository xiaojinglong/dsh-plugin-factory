# Shopee Listing 分析节点流程（业务说明）

> 给运营/业务同学阅读，用于对齐流程与留存；不参与程序执行。

## 1. 业务目标

回答三个问题：
1. 某负责人名下的在售商品，结构与分布是否健康？
2. 库存、动销、内容质量、合规上存在哪些具体问题？
3. 下一步先做什么（按影响排序）？

产出：一份单文件 HTML 报告。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 业务发起人 | 指定负责人（shop_user_id/姓名）、范围与页数 |
| Skill（AI） | 取数、统计、生成报告与建议 |
| listing 服务 | 调用开放接口取数并落盘 |
| 主管 | 验收报告，抽查 1–2 个数字与后台对照 |

## 3. 节点流程

### 节点 1：确认范围
默认：负责人 陈雄德（shop_user_id=632016）、在售（NORMAL）、2 页。
可调：页数（≤10）、负责人、状态。

### 节点 2：提交取数任务
向 listing 服务提交任务，参数含页数与负责人。

### 节点 3：等待取数
正常几秒完成；失败则看原因，最多重试 1 次。

### 节点 4：获取数据
得到 `listing_dataset.json`（2 页商品 + 全量总数）。

### 节点 5：统计与诊断
结构（状态/站点/类目/价格带）、库存（零库存/低库存/滞销）、动销（30 天有单、浏览转化）、质量合规（违禁、敏感词、相似标题图、视频、广告）。

### 节点 6：输出报告
HTML 8 节：结论、口径、结构、库存动销、质量合规、异常清单、优化建议、附录。

### 节点 7：输出与验收
主管抽 1–2 个数字（如零库存数、库存总量）与后台对照，一致即通过。

## 4. 输入与输出

**输入**：负责人、状态、页数、凭证（服务端配置）
**输出**：HTML 报告 + `listing_dataset.json`

## 5. 异常处理

| 情况 | 处理 |
|---|---|
| 接口鉴权失败 | 检查凭证；不重试 |
| 接口 500 | 参数类型问题，改最小参数重试 1 次 |
| 数据为空 | 输出"无数据"，不生成建议 |
| 部分字段为 0 | 视为无数据，不参与统计 |
| 跨站点金额 | 不直接相加 |

## 6. 口径说明

- 数据范围：负责人名下的**在售**商品；草稿不计入。
- 采样：2 页（业务约定），非全量。
- 价格：站点原币种；库存：件数。
- 报告中的数字必须能追溯到数据文件，禁止编造。
