# 经营分析节点流程（业务说明）

> 本文档给运营/业务同学阅读，用于对齐流程与留存；不参与程序执行。

## 1. 业务目标

基于「平台经营分析」报表与各店铺订单明细，回答：

1. 哪些店铺经营达标（**毛利率 ≥ 15%**）？
2. 达标店铺的利润被哪些产品、哪些经营参数拖累？
3. 下一步怎么优化（可执行动作 + 预期影响）？

最终产出：一份按店铺、按产品的经营分析报告 + 优化建议。

## 2. 角色与职责

| 角色 | 职责 |
|---|---|
| 业务发起人 | 确认分析范围（平台/线路/站长/周期）与毛利率阈值 |
| 运营/店长 | 提供业务背景，确认建议是否可执行 |
| Skill（AI） | 取数、分析、输出报告与优化建议 |
| 爬虫服务 | 登录目标系统、导出汇总表与订单明细 |
| 人工（首次/失效时） | 完成扫码/授权，恢复登录状态 |
| 运营主管 | 验收报告，抽查数据 |

## 3. 节点流程

### 节点 1：确认范围
- 默认：平台 shopee、线路 新加坡、站长 丁月。
- 可调整：店铺范围、毛利率阈值（默认 15%）、数据周期说明。

### 节点 2：提交取数任务
- 向爬虫服务提交「经营分析」取数任务。
- 提交后等待任务完成。

### 节点 3：等待取数
- 正常：等待任务完成。
- 需要扫码：通知发起人完成扫码/授权，完成后继续。
- 失败：输出失败原因，最多重试 1 次。

### 节点 4：获取报表
- 汇总表：每个店铺一行，含平台/线路/站点负责人/站点名称/店铺名/毛利润/运营成本/净利润/净利率等。
- 订单明细：每个店铺一份，产品/订单级数据。
- 缺失店铺：单独列出，不用汇总数据替代明细。

### 节点 5：筛选达标店铺
- 计算店铺毛利率（报表有毛利率列直接用；没有则 毛利润 ÷ 销售额）。
- **毛利率 ≥ 15%** → 进入深度分析。
- 毛利率 < 15% → 进入预警清单，给 1~2 条止损建议。

### 节点 6：关联产品级明细
- 按【站点名称】把店铺与订单明细一一对应。
- 按产品聚合：销售额、毛利润、毛利率、订单量、退款、广告费等。
- 找出：高贡献产品、低毛利产品、亏损产品、高退款产品。

### 节点 7：参数诊断
逐项看（有数据才算）：
- 产品结构、定价/折扣、广告投入、退款、采购/物流/佣金成本、店铺评分与罚分、订单结构。
- 每项说明：现状 → 与利润的关系 → 是否问题 → 影响大/中/小。

### 节点 8：输出优化建议
- 每个达标店铺 3~5 条可执行建议，必须带数据依据与预期影响；
- 按“影响大、可执行、成本低”排序；
- 给出 3 条跨店铺结论。

### 节点 9：输出与验收
- 报告结构：结论摘要 → 数据口径 → 达标店铺 → 产品级分析 → 参数诊断 → 优化建议 → 预警 → 附件。
- 运营主管抽查 1~2 家明细与页面数据对照，数字一致即通过。

## 4. 输入与输出

**输入**
- 平台/线路/站长、店铺范围、数据周期
- 毛利率阈值（默认 15%）
- 爬虫服务地址与配置（由技术侧维护）

**输出**
- 经营分析报告（Markdown）
- 引用附件：汇总表、各店铺明细、任务编号
- 预警店铺清单与建议

## 5. 异常处理

| 情况 | 处理 |
|---|---|
| 需要扫码/授权 | 通知发起人处理，完成后继续 |
| 取数失败 | 重试 1 次；仍失败输出原因，不编造数据 |
| 明细缺失 | 单列说明，不做产品级分析 |
| 报表缺列 | 标注缺列，跳过对应分析 |
| 毛利率无法计算 | 标注原因，不纳入达标/预警结论 |
| 数据为空 | 输出“无数据”，不生成建议 |

## 6. 口径说明

- 毛利率 = 毛利润 ÷ 销售额（报表有毛利率列则直接用；销售额列按实际表头识别）。
- 阈值 15%：低于阈值进入预警，不等同于亏损。
- 产品毛利按产品聚合；退款、广告费等字段如缺失则跳过该参数，不估算。
- 金额单位/币种、时区、数据周期沿用报表口径（待确认）。
- 报告中的每个数字必须能追溯到具体文件、列、行，禁止编造。
