# 经营分析 Skill（concise-analysis）

> 业务展示名：ConciseAnalysis（仅展示用）；DSH skill 标识：`concise-analysis`（kebab-case）。

## 1. 适用场景

- 对「平台经营分析」报表做经营分析：先看店铺，再下钻到产品/订单级明细。
- 分析条件：**店铺毛利率 ≥ 15%** 的店铺为重点分析对象；低于 15% 的店铺输出预警。
- 产出：店铺经营诊断 + 产品级问题定位 + 可执行优化建议。
- 边界：**只读分析**，不修改任何业务系统；不直接访问页面，页面自动化由爬虫服务完成。

## 2. 前置条件与输入

数据来源（单一爬虫服务，一次任务产出两类文件）：
- 汇总表：每个店铺一行，店铺级数据；
- 订单明细：每个店铺一份，产品/订单级数据；
- 缺失清单：未取到明细的店铺。

默认口径（可由用户覆盖）：
- 平台 `shopee`、线路 `新加坡`、站长 `丁月`
- 维度：平台、线路、店铺名（保留站点名称）
- 指标：毛利润、运营成本、净利润、净利率
- 毛利率阈值：`15%`（重点分析线）
- 数据周期：沿用报表默认（本次不额外指定日期）

用户可输入：
- 平台/线路/站长、店铺范围、毛利率阈值（覆盖需在报告注明）。

数据粒度与口径：
- 汇总表：店铺级；订单明细：产品/订单级；关联键为【站点名称】。
- 金额币种/单位、时区：沿用报表【待确认】。

## 3. 工具清单（concise-analysis-mcp）

| 工具 | 用途 | 关键参数 |
|---|---|---|
| `submit_task` | 提交取数任务 | `taskType: "jingying_analysis"`、`params`（可选覆盖筛选） |
| `get_task_status` | 查询任务状态 | `taskId`；`waiting_verify` 时返回 `verifyUrl` |
| `wait_task` | 轮询到终态 | `taskId` |
| `get_task_result` | 取产物清单 | `taskId`；返回 `main`、`details[]`、`missingItems[]` |
| `read_result_file` | 读取/解析 xlsx/csv/json | `filePath`、`sheet`（可选） |

说明：
- 本业务**没有写操作**，不需要审批 Gate；如后续要加“推送建议到外部系统”，必须单独设计审批。
- 不编造不存在的工具；工具名以实际薄壳为准。

## 4. 业务编排流程

### 4.1 参数确认
确认平台/线路/站长、店铺范围、毛利率阈值（默认 15%）、数据周期说明（默认沿用报表）。

### 4.2 提交取数任务
```
submit_task(taskType="jingying_analysis", params={})
```
- 空 `params` 即默认口径；
- 需要改筛选时传 `platform/line/station/dimensions/metrics`；
- 提交后记录 `taskId`。

### 4.3 等待任务
```
wait_task(taskId)
```
- `succeeded` → 4.4；
- `waiting_verify` → 返回 `verifyUrl` 给用户扫码，**暂停**；人工完成后重新查询；
- `failed` → 输出 `error` 与已有产物；最多重试 1 次（同参数）。

### 4.4 获取产物
```
get_task_result(taskId)
```
- `main`：汇总表（店铺级）；
- `details[]`：各店订单明细（`itemName` = 站点名称）；
- `missingItems[]`：未取到明细的店铺，报告中单列。

### 4.5 读取汇总表并计算毛利率
```
read_result_file(main.path)
```
- 识别必需列：`平台、线路、站点负责人、站点名称、店铺名、毛利润、运营成本、净利润、净利率`；
- 数值清洗：去千分位/货币符号/空白；百分比转小数；
- 毛利率：
  1. 有 `毛利率` 列 → 直接使用；
  2. 无该列 → `毛利率 = 毛利润 ÷ 销售额`；销售额列按实际表头识别（如 `订单合计`、`销售额`、`有效订单金额`）；
  3. 无法计算 → 标记“毛利率不可计算”，不参与筛选。

### 4.5.1 实际字段校准（2026-11-13 实测）

- 汇总表实际列名：`收入合计`（销售额口径）、`毛利率`（已存在，直接使用）、`退损率`、`物流占比`、`采购占比`、`广告占比`、`平台佣金占比`、`VAT金额占比` 等；
- `平台=合计` 的汇总行：站点名称为空，分析时**必须剔除**；
- 合并单元格：`平台/线路/团队/站点负责人` 只在组首行有值，需要按 `站点名称` 关联或向下填充；
- 特殊值：零销售额时 `毛利率` 可能为 `–∞`、`净利率` 可能为空 → 视为“不可计算”，不参与排名；
- 销售额列顺序：优先 `收入合计`，其次 `订单合计/销售额/有效订单金额`。

### 4.6 筛选店铺
- 重点分析集：`毛利率 ≥ 0.15`；
- 预警集：`毛利率 < 0.15`，输出店铺名、毛利率、毛利润、订单量 + 1~2 条止损建议；
- 重点集为空：输出“整体未达标”，给提升毛利率的总体建议。

### 4.7 关联产品级明细
对重点分析集的每个店铺：
1. 用 `details[].itemName` 与汇总表【站点名称】精确匹配；
2. `read_result_file(detail.path)` 读取产品/订单级数据；
3. 按实际表头识别字段：产品/Listing/商品ID、订单量、销售额、毛利润、毛利率、退款、广告费、采购成本、物流/佣金等（缺列跳过并标注）；
4. 按产品聚合：销售额、毛利润、毛利率、订单量、退款率、广告费占比；
5. 标记：高贡献产品、低毛利产品、亏损产品、高退款产品。

> 明细缺失（`missingItems`）的店铺：报告单列，禁止用汇总表数据伪造产品级分析。

### 4.7.1 明细实际结构（2026-11-13 实测）

- 明细是**订单级**，不是单品级；列包括：订单号、下单时间、订单商品数量、`订单产品列表`（商品 ID 列表）、有效订单额、`毛利润（估）`、`毛利率（估）`、卖家订单额、退款金额、头程、尾程&全程、运费回扣、头程手续费、采购成本、平台佣金、活动手续费、结算手续费、VAT金额、平均广告花费（估）、平均运营成本（估）；
- 首行是**汇总行**（订单号形如 `有效订单量：1`），分析前必须剔除；
- 产品级：`订单产品列表` 只是商品 ID 列表，当前**没有单品金额拆分**；只能按订单/产品组合分析，不能虚构“单品利润”；
- 订单级可分析：订单毛利率、退款/退货、头程/尾程/运费回扣、采购成本、平台佣金、广告花费、运营成本。

### 4.8 参数诊断（每店）
结合汇总表 + 产品级明细逐项判断（有数据才分析，无数据标“缺列”）：
- 产品结构：低毛利/亏损产品占销售额比例；
- 定价与折扣：毛利率与折扣率、活动折扣关系；
- 广告：广告费占销售额比例，广告带来销量与毛利是否匹配；
- 退款：退款率、退款金额对净利润的侵蚀；
- 成本：运营成本、采购成本、平台佣金、物流/VAT 占比；
- 店铺健康：评分、罚分、预售比例、上架/库存情况；
- 订单结构：订单量、客单价、买家数。

每项输出：**现状值 → 与毛利率/利润关系 → 是否问题 → 影响程度（高/中/低）**。

### 4.9 生成优化建议
- 每个重点店铺 3~5 条可执行建议，必须带数据依据与预期影响；
- 示例方向：下架/整改亏损产品、提价或换货源、广告预算调整、退款治理、产品结构优化；
- 按“影响大、可执行、成本低”排序；另给 3 条跨店铺结论。

### 4.10 输出报告
按第 7 节模板输出；附任务 ID、文件路径、缺失清单。

## 5. 数据分析规则

| 指标 | 公式/规则 | 边界 |
|---|---|---|
| 店铺毛利率 | 毛利率列，或 毛利润 ÷ 销售额 | 销售额=0 → 不可计算 |
| 产品毛利率 | 产品毛利润 ÷ 产品销售额 | 销售额=0 → 不可计算 |
| 产品销售额占比 | 产品销售额 ÷ 店铺销售额 | 用于结构分析 |
| 退款率 | 退款金额 ÷ 销售额（或退款单数 ÷ 订单数，按实际字段） | 字段缺失 → 跳过 |
| 广告费占比 | 广告费 ÷ 销售额 | 字段缺失 → 跳过 |

- 金额保留 2 位小数；比例输出百分比保留 1 位。
- 缺失值（空、`-`、`~`）按缺失处理，不参与计算，报告列出。
- 所有结论数字必须能追溯到具体文件/列/行。

## 6. 数据校验规则

- 汇总表必须含 4 个指标列与店铺维度列，否则停止分析并说明缺列。
- 店铺匹配：`details[].itemName` 与【站点名称】精确匹配；匹配不上列入“未关联明细”。
- 产品聚合后校验：`Σ产品销售额 ≈ 店铺销售额`（允许 5% 业务误差，超出标注）。
- 主键唯一：店铺按站点名称唯一；产品按产品ID/Listing 唯一（以实际为准）。
- 缺文件/缺列/缺失店铺全部进入“缺失清单”，报告中单列。

```

## 二、数据口径
- 数据来源与任务 ID；汇总表/明细份数；筛选条件；毛利率阈值（默认 ≥15%）
- 缺失/异常说明（missingItems、无法计算的店铺）

## 三、达标店铺分析（毛利率 ≥ 15%）
| 店铺 | 站点名称 | 销售额 | 毛利润 | 毛利率 | 净利润 | 主要问题 |

## 四、产品级分析（逐店）
### <店铺名>
- 高贡献产品 / 低毛利产品 / 亏损产品 / 高退款产品
- 产品结构与毛利贡献

## 五、参数诊断
- 产品结构 / 定价折扣 / 广告 / 退款 / 成本 / 店铺健康 / 订单结构：现状、问题、影响

## 六、优化建议
- 按店铺 3~5 条，按优先级排序；每条附数据依据与预期影响

## 七、预警（毛利率 < 15%）
| 店铺 | 毛利率 | 毛利润 | 建议动作 |

## 八、附件
- 汇总表路径、明细路径、任务 ID
```

## 8. 异常与重试

| 场景 | 处理 |
|---|---|
| `waiting_verify` | 返回 `verifyUrl` 让用户扫码；暂停，不自动重试 |
| 轮询超时 | 再 `get_task_status` 一次；仍无终态则输出超时说明 |
| `failed` | 原样输出 `error`；最多重新提交 1 次 |
| 明细缺失 | 列入缺失清单，不伪造产品级分析 |
| 列缺失 | 标注“缺列”，跳过对应分析，不影响其它结论 |
| 文件读取失败 | 报告路径与错误；同一路径最多重试 2 次 |
| 销售额=0/数据为空 | 标记“不可计算/无数据”，不参与排名 |

## 9. 维护与扩展

- 阈值调整：同步修改第 2、4.6 节并在报告注明。
- 新增分析参数：确保数据源有对应列，再在第 4.8 节追加；无列则标缺列。
- 切换数据源/后端：只改 MCP 薄壳与 `config.json`，本 Skill 不变。
- 版本记录：v1.1（补充触发词、数据粒度/币种待确认、复杂编排说明、验收口径）。
